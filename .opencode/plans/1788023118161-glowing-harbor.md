# Use OxDock's EXPAND for Template Expansion in docs-gen

## Goal

Replace the manual `HashMap`-based string replacement in `crate_readme.rs` with OxDock's native `EXPAND` command. Rust handles metadata extraction; OxDock handles template rendering and file output via stream piping.

## Architecture

```
docs-gen (Rust)                    OxDock DSL
─────────────────                  ──────────
parse Cargo.toml ──► ENV vars ──► INHERIT_ENV
load section files ──► ENV vars ──► EXPAND template ──pipe──► WRITE README.md
discover crates ──► loop per crate
```

## Implementation

### 2. Replace `generate_one()` in `crate_readme.rs`

Stream directly to file via OxDock pipe — no `CapturingWriter`, no `Arc`, no `Mutex`:

```rust
fn generate_one(
    template_path: &Path,
    crate_dir: &Path,
    cargo_toml: &Path,
    repo_root: &Path,
) -> Result<()> {
    use oxdock_core::{run_steps_with_context_result_with_io, ExecIo};
    use oxdock_fs::GuardedPath;
    use oxdock_parser::parse_script;

    let metadata = parse_cargo_metadata(cargo_toml)?;
    let source_files = load_source_files(crate_dir, &metadata.name);

    let mut vars = HashMap::new();
    vars.insert("CRATE_NAME".to_string(), metadata.name);
    vars.insert("CRATE_DESCRIPTION".to_string(), metadata.description);
    vars.insert("CRATE_OVERVIEW".to_string(), source_files.overview);
    vars.insert("CRATE_QUICK_START".to_string(), source_files.quick_start);
    vars.insert("CRATE_API".to_string(), source_files.api);

    let target_dir = cargo_toml.parent().context("invalid Cargo.toml path")?;
    let readme_path = target_dir.join("README.md");

    // Sort keys deterministically (HashMap iteration order is random)
    let mut keys: Vec<_> = vars.keys().cloned().collect();
    keys.sort();

    // Normalize paths to forward slashes for DSL compatibility (Windows backslashes corrupt lexer tokens)
    let norm_template = template_path.to_string_lossy().replace('\\', "/");
    let norm_readme = readme_path.to_string_lossy().replace('\\', "/");

    let script = format!(
        "INHERIT_ENV [{}]\nWORKSPACE LOCAL\nWITH_IO [stdout=pipe:out] EXPAND \"{}\"\nWITH_IO [stdin=pipe:out] WRITE \"{}\"",
        keys.join(", "),
        norm_template,
        norm_readme
    );

    let mut io = ExecIo::new();
    for (key, value) in &vars {
        io.insert_inherit_env(key, value);
    }

    let root = GuardedPath::new_root(repo_root)?;
    let temp = GuardedPath::tempdir()?;
    let steps = parse_script(&script)?;

    run_steps_with_context_result_with_io(
        temp.as_guarded_path(),
        &root,
        &steps,
        io,
    )?;

    Ok(())
}
```

## Key Design Decisions

- **WORKSPACE LOCAL**: Required to write output to the real repository instead of the disposable temp scratchpad
- **Pipe-based output**: `WITH_IO [stdout=pipe:out] EXPAND ...` + `WITH_IO [stdin=pipe:out] WRITE ...` streams directly to file, eliminating buffer bouncing
- **Deterministic keys**: `keys.sort()` before `INHERIT_ENV [...]` ensures stable script strings across runs
- **Forward-slash normalization**: `replace('\\', "/")` prevents Windows backslash corruption in the OxDock lexer
- **Quoted paths**: Double-quote wrapping prevents tokenization failures on paths with whitespace
- **No `CapturingWriter`**: The entire capture-and-write boilerplate is eliminated
