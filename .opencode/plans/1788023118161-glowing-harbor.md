# Fix: `WITH_IO` assertion window key desynchronization

## Problem

`pre_register_assertions` pre-registers `WITH_IO`-wrapped `ASSERT_STDOUT` windows under the parent's `(generation, idx)` key. But `handlers::with_io` calls `execute_steps` which allocates a **new** generation and resets the child step index to `0`. When `handlers::assert_stdout` executes, it looks up `(new_generation, 0)` instead of `(parent_generation, parent_idx)`, missing the pre-registered window.

## Fix

Add `execute_single_step_with_generation` back to `steps.rs` with complete variant coverage. Have `with_io` call it instead of `execute_steps`, forwarding the parent's `generation` and `idx`.

## Files to Modify

### 1. `crates/oxdock-core/src/exec/steps.rs`

Add `execute_single_step_with_generation` that:
- Takes `cmd: &StepKind`, `generation: usize`, `idx: usize`
- Builds a `StepCtx` and dispatches the single step using the parent's index
- Handles ALL executable `StepKind` variants:
  - **Stream-redirectable commands**: Run, Echo, RunBg, Write, RawWrite (path resolved via `resolve_arg`, contents bypasses template expansion but resolves `$variable`), Append, Read, Copy, CopyGit, HashSha256, Symlink, Mkdir, Ls, Cwd, Expand, AssertFile, AssertDir, AssertAbsent, AssertStdout, Workdir
  - **State-mutating directives**: Workspace, InheritEnv (both work safely inside `StepCtx`)
  - **Chained I/O**: WithIo (recursively forwards parent `generation` and `idx`)
- Only bails on: WithIoBlock (parser should have expanded), Exit (kills children), For/Assign (control flow — not valid inside I/O redirect)

### 2. `crates/oxdock-core/src/exec/handlers.rs`

Update `with_io` to call `execute_single_step_with_generation` instead of `execute_steps`:

```rust
pub(super) fn with_io<P: ProcessManager>(
    cx: &mut StepCtx<'_, P>,
    generation: usize,
    idx: usize,
    bindings: &[IoBinding],
    cmd: &StepKind,
) -> Result<()> {
    // ... setup teed I/O handles (unchanged) ...
    super::steps::execute_single_step_with_generation(
        cx.state,
        cx.process,
        cmd,
        generation,
        idx,
        step_stdin,
        next_expose_stdin,
        step_stdout,
        step_stderr,
    )
}
```

### 3. `crates/oxdock-core/src/exec/steps.rs` — dispatch loop (no change needed)

The dispatch loop already passes `generation` and `idx` to `with_io`:
```rust
handlers::with_io(&mut cx, generation, idx, bindings, cmd)
```
