# OxDock Engine Extensions: FOR, GLOB, $variable

## Goal

Add control flow and expression evaluation to OxDock's DSL engine: `FOR` loops, `GLOB` expressions, `LET` assignments, and `$variable` interpolation. This expands OxDock from a sequential command DSL into a general-purpose orchestration engine.

## Design Decisions (User-Confirmed)

- **FOR loop AST**: Tree node (`StepKind::For { var, in_expr, body }`) — runtime glob evaluation requires this
- **Variable syntax**: Separate `$variable` binding with scope resolution, distinct from `{{ env:KEY }}` templates
- **GLOB form**: First-class expression (`Expr`) usable in `FOR` loops and standalone `LET` assignments
- **Expression system**: Unified `Expr` enum with `Literal`, `Var`, `Call` variants for extensibility

## Architecture

```
┌─────────────────────────────────────────────────────────┐
│ oxdock-parser                                           │
│  - New tokens: FOR, IN, LET, IDENT, DOLLAR_IDENT       │
│  - New AST: Expr, StepKind::For, StepKind::Assign      │
│  - Grammar: for_statement, let_statement, expr, args   │
└───────────────────┬─────────────────────────────────────┘
                    │
                    ▼
┌─────────────────────────────────────────────────────────┐
│ oxdock-core                                             │
│  - Variable Scope Stack (Vec<HashMap<String, Value>>)   │
│  - Expr evaluator (Literal → Value, Call → handler)     │
│  - FOR handler: push scope, set $var, exec body, pop   │
│  - Glob resolver (resolves against GuardedPath root)    │
│  - $var interpolation in step arguments only            │
└─────────────────────────────────────────────────────────┘
```

**Note:** `StreamingExpand` in `oxdock-process` is NOT modified. `$variable` interpolation happens exclusively in `oxdock-core` during step argument evaluation, not in template payload processing. This prevents corruption of literal shell variables (`$PATH`, `$0`, etc.) inside files processed by `EXPAND`.

## DSL Syntax Examples

```oxdock
# Standalone assignment
LET $files = GLOB("docs/sections/*.md")

# FOR loop with inline GLOB
FOR $f IN GLOB("docs/sections/*.md") {
    READ "$f"
    APPEND "README.md" "\n\n"
}

# FOR loop over variable
FOR $f IN $files {
    READ "$f"
}

# Nested loops
FOR $dir IN GLOB("crates/*/src") {
    FOR $f IN GLOB("$dir/**/*.rs") {
        READ "$f"
    }
}

# $variable in commands
LET $name = "hello"
WRITE "$name.txt" "content"
```

## Implementation Steps

### Step 1: Parser — Expression AST (`oxdock-parser/src/ast.rs`)

Add new types for the expression system:

```rust
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Value {
    String(String),
    List(Vec<String>),
    Bool(bool),
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Expr {
    Literal(Value),
    Var(String),
    Call { name: String, args: Vec<Expr> },
}

#[derive(Debug, Clone, PartialEq, Eq)]
pub enum StepKind {
    // ... existing 24 variants unchanged
    For {
        var: String,
        in_expr: Expr,
        body: Vec<Step>,
    },
    Assign {
        var: String,
        expr: Expr,
    },
}
```

Add `$var` token support to `TemplateString` or a new `Arg` type that can carry either a literal, a `{{ env:KEY }}` placeholder, or a `$var` reference.

### Step 2: Grammar — PEG Rules (`oxdock-parser/src/dsl.pest`)

Add new grammar rules:

```pest
// Expressions
for_statement = { "FOR" ~ sep ~ dollar_ident ~ sep ~ "IN" ~ sep ~ expr ~ sep ~ block }
let_statement = { "LET" ~ sep ~ dollar_ident ~ sep ~ "=" ~ sep ~ expr }
expr = { func_call | variable | list_literal | string_literal }
func_call = { ident ~ "(" ~ (expr ~ ("," ~ expr)*)? ~ ")" }
variable = @{ "$" ~ ident }
list_literal = { "[" ~ (expr ~ ("," ~ expr)*)? ~ "]" }

// $variable in arguments
dollar_ident = @{ "$" ~ ident_char+ }
argument = { quoted_string | templated_arg | dollar_variable | unquoted_arg }
dollar_variable = @{ "$" ~ ident_char+ }
```

### Step 3: Lexer — New Tokens (`oxdock-parser/src/lexer.rs`)

Add token variants for `FOR`, `IN`, `LET`, `DOLLAR_IDENT`.

### Step 4: Parser — Statement Parsing (`oxdock-parser/src/parser.rs`)

Extend `ScriptParser` to:
1. Recognize `FOR` token and parse the for_statement
2. Recognize `LET` token and parse the let_statement
3. Parse `Expr` recursively (func_call, variable, literal)
4. Build `StepKind::For { var, in_expr, body }` tree node with nested body steps
5. Build `StepKind::Assign { var, expr }` node

### Step 5: Executor — Scope Stack (`oxdock-core/src/exec/state.rs`)

Add a variable scope stack to `ExecState` using `Value` (not `String`) to support list variables:

```rust
pub(super) struct ExecState {
    // ... existing fields
    pub(super) var_scopes: Vec<HashMap<String, Value>>,  // NEW: $variable scopes
}
```

Methods:
- `push_scope()`: Pushes empty HashMap onto `var_scopes`
- `pop_scope()`: Pops from `var_scopes`
- `set_var(key, value: Value)`: Sets in innermost scope
- `get_var(key)`: Walks scopes from innermost to outermost, returns `Option<Value>`

### Step 6: Executor — FOR Handler (`oxdock-core/src/exec/handlers.rs`)

New handler with RAII-safe scope cleanup:

```rust
fn for_loop(ctx, var, in_expr, body) -> Result<()> {
    let iterable = evaluate_expr(&in_expr, ctx)?;
    // Strip '$' prefix for storage key consistency
    let clean_var = var.trim_start_matches('$').to_string();

    if let Value::List(items) = iterable {
        for item in items {
            ctx.state.push_scope();
            ctx.state.set_var(clean_var.clone(), Value::String(item));
            let res = execute_steps(ctx.state, ctx.process, body);
            ctx.state.pop_scope();
            res?; // Check error AFTER pop_scope to prevent frame leak
        }
        Ok(())
    } else {
        bail!("FOR loop requires a list iterable")
    }
}
```

### Step 7: Executor — LET Handler

```rust
fn assign(ctx, var, expr) -> Result<()> {
    let value = evaluate_expr(expr, ctx)?;
    // Strip '$' prefix for storage key consistency
    let clean_var = var.trim_start_matches('$').to_string();
    ctx.state.set_var(clean_var, value);
    Ok(())
}
```

### Step 8: Executor — Expr Evaluator

Resolve `$variable` references in string literals to support nested expressions like `GLOB("$dir/**/*.rs")`:

```rust
fn evaluate_expr(expr: &Expr, ctx: &mut StepCtx) -> Result<Value> {
    match expr {
        Expr::Literal(Value::String(s)) => {
            // Resolve embedded $variable references in string literals
            Ok(Value::String(resolve_dollar_vars(s, &ctx.state)))
        }
        Expr::Literal(v) => Ok(v.clone()),
        Expr::Var(name) => ctx.state.get_var(name)
            .ok_or_else(|| anyhow!("undefined variable ${name}")),
        Expr::Call { name, args } => {
            match name.as_str() {
                "GLOB" => evaluate_glob(args, ctx),
                _ => bail!("unknown function {name}")
            }
        }
    }
}
```

### Step 9: Executor — GLOB Resolver

Escape root path metacharacters and normalize Windows separators:

```rust
fn evaluate_glob(args: &[Expr], ctx: &mut StepCtx) -> Result<Value> {
    if args.is_empty() {
        bail!("GLOB requires a pattern argument");
    }

    let pattern_val = evaluate_expr(&args[0], ctx)?;
    let raw_pattern = match pattern_val {
        Value::String(s) => s,
        _ => bail!("GLOB pattern argument must evaluate to a string"),
    };

    // Normalize backslashes to forward slashes before escaping (Windows paths)
    let norm_root = ctx.root.as_path().to_string_lossy().replace('\\', "/");
    let escaped_root = glob::Pattern::escape(&norm_root);
    let full_pattern = format!("{}/{}", escaped_root, raw_pattern.trim_start_matches('/'));

    let mut entries: Vec<String> = glob::glob(&full_pattern)?
        .filter_map(|e| e.ok())
        // Strip root prefix to return workspace-relative paths
        .filter_map(|p| p.strip_prefix(ctx.root.as_path()).ok())
        .map(|rel| rel.to_string_lossy().replace('\\', "/"))
        .collect();

    entries.sort(); // Deterministic order
    Ok(Value::List(entries))
}
```

### Step 10: Executor — $variable Interpolation in Step Arguments

`$variable` interpolation happens in `oxdock-core` during step argument evaluation, NOT in `StreamingExpand`. When a command handler receives a `TemplateString`, it first resolves `$var` references using the scope stack, then passes the result to `expand_template()` for `{{ env:KEY }}` resolution.

**Key invariant:** Variable keys are stored WITHOUT the `$` prefix (e.g., `"f"` not `"$f"`). The parser strips `$` from both declarations (`LET $f = ...` → key `"f"`) and references (`$f` → lookup `"f"`).

```rust
fn resolve_dollar_vars(input: &str, ctx: &ExecState) -> String {
    let mut result = String::new();
    let mut chars = input.chars().peekable();
    while let Some(c) = chars.next() {
        if c == '$' {
            let mut name = String::new();
            while let Some(&ch) = chars.peek() {
                if ch.is_alphanumeric() || ch == '_' {
                    name.push(ch);
                    chars.next();
                } else {
                    break;
                }
            }
            // Lookup uses clean name (without '$' prefix)
            if let Some(value) = ctx.get_var(&name) {
                match value {
                    Value::String(s) => result.push_str(&s),
                    Value::List(items) => result.push_str(&items.join(" ")),
                    Value::Bool(b) => result.push_str(&b.to_string()),
                }
            } else {
                result.push('$');
                result.push_str(&name);
            }
        } else {
            result.push(c);
        }
    }
    result
}
```

This is called in each command handler before `expand_template()`:

```rust
fn read_handler(ctx) -> Result<()> {
    let path = resolve_dollar_vars(&ctx.step_path, &ctx.state);
    let path = expand_template(&TemplateString(path), &ctx.command_ctx());
    // ... perform read
}
```

### Step 11: Template Expansion — No Changes to StreamingExpand

`StreamingExpand` in `oxdock-process` is NOT modified. It continues to handle only `{{ env:KEY }}` placeholders. The `$variable` interpolation is fully resolved before template expansion runs, so `StreamingExpand` never sees `$var` tokens.
