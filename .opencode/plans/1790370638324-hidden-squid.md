# Plan for #179: Portable OxDock builder plugin (single atomic change, v1 local source bundle)

## Decisions locked from user (2026-09-25)
- Single atomic change, not incremental milestones. All pieces land together.
- TLS stack locked per review verdict: pure-Rust only (`ureq` with `rustls` and `webpki-roots`). Prohibits `aws-lc-rs` and `openssl` in `NET_FETCH` because they require a host C compiler and `cmake`.
- V1 source acquisition: bundle the local source. No NET tarball or COPY_GIT pinned fetch in v1. All writes still isolated under the toolchain cache group. Pinned remote source fetch is follow-up.

## Background
- No FETCH DSL exists. `StepKind` in `crates/oxdock-parser/src/commands.rs` has no network fetch. Network surface lives in `crates/plugins/oxdock-net-plugin` as `NET_*` host funcs.
- Only cache group today is `workspace` in `crates/sys/oxdock-fs/src/workspace_fs/cache.rs` (`CACHE_GROUP`, `resolve_cache_dir`, `cache_guard_for`, `ensure_cache_dir` via `CacheRoot::ensure_group`, creation-only, never evict). Only `cache-manager 0.4.1` consumer is `oxdock-fs`.
- Plugin precedent: `crates/plugins/oxdock-ssh-plugin` and `oxdock-net-plugin` each expose `module() -> HostModule<DefaultProcessManager>` plus generic `module_with::<P: ProcessManager>()`, with `#[oxdock_func]` funcs in `src/funcs.rs` and hand-built `HostRegistration::Stateful` entries when capturing `Arc<EndpointRegistry>`.
- This issue is the local portable-build half of #158. Remote ship and exec over SSH are explicitly out of v1.

## Implementation (single atomic change, ordered steps)

### Step 1. `oxdock-fs`: dedicated `toolchain` cache group (narrow scope)
Files: `crates/sys/oxdock-fs/src/workspace_fs/cache.rs`, `crates/sys/oxdock-fs/src/workspace_fs/mod.rs`.

- Add `pub(crate) const TOOLCHAIN_GROUP: &str = "toolchain"` next to `CACHE_GROUP`. Keep `CACHE_GROUP = "workspace"` untouched and stable.
- Expose a narrow helper on `PathResolver` (for example `pub fn toolchain_guard(&self) -> GuardedPath`) resolving `<cache-root>/toolchain` without raw `std::fs` or ad-hoc string joins. Back it with `toolchain_guard_for(explicit)` and `ensure_toolchain_dir` creation-only helpers mirroring the existing cache trio (`CacheRoot::ensure_group(TOOLCHAIN_GROUP)`, never evict).
- Do not add `switch_to_toolchain_cache` to the `WorkspaceFs` trait, `MockFs`, `CurrentRoot`, or `resolve.rs` choke points. `toolchain` is an internal cache group, not a DSL `WORKSPACE` target. When the toolchain plugin runs an isolated compilation, it initializes its internal `PathResolver` directly with the `toolchain_guard` as root.
- All guarded I/O through `GuardedPath` and `PathResolver`. Normalize via existing helpers. No raw `std::fs` for guarded paths, no direct `tempfile` outside `oxdock-fs`.
- Tests: mirror `ensure_cache_dir_creates_without_evicting` for the toolchain group, using `SerialCacheEnv` to pin `OXDOCK_CACHE_DIR`.

### Step 2. `oxdock-net-plugin`: `NET_FETCH` download surface (pure-Rust TLS)
Files: `crates/plugins/oxdock-net-plugin/src/funcs.rs`, `src/lib.rs`, `src/bridge.rs` or new `src/fetch.rs`, `Cargo.toml`, `.oxdock/template/...`, `tests/integration/net.rs`.

- Add `NET_FETCH(url, dest_or_pipe, options)` as hand-built `HostRegistration::Stateful` capturing `Arc<EndpointRegistry>` (macro cannot capture registry), following `NET_CONNECT` and `SSH_CONNECT` patterns.
- Behavior: HTTPS GET with redirect following, writes to a guarded path or explicit pipe, `sha256` option verified on the wire, `timeout` and `retries` options. Options MAP with unknown keys bailing. Offline gate first: `bail!("NET_FETCH failed: engine running in --offline mode")`.
- Execution mode: synchronous file download when the destination is a file path (`GuardedPath`). Reserve `ASYNC` execution rules strictly for unbuffered `PIPE` destinations (blocking pump requires `ASYNC` guard like `NET_ACCEPT`).
- TLS locked: `ureq` configured with `rustls` and `webpki-roots` in `crates/plugins/oxdock-net-plugin/Cargo.toml`. Prohibit C-dependent crypto (`aws-lc-rs`, `openssl`) in `NET_FETCH` because they require a host C compiler and `cmake`, violating the bare-Linux no-C-toolchain requirement. Bare Linux needs no system openssl, curl, or CA tooling. No sockets opened outside the NET module. Keep pipe conventions (`out_pipe` is wire-produced, `in_pipe` is wire-consumed, full-duplex pumps, supervisor tick for cancel).
- Docs fence in func docs (`IMPORT [STD, NET]`, hermetic loopback or memory rendezvous, `INSPECT` poll loop, `ASSERT_CONTAINS`, `CANCEL` plus `NET_CLOSE` teardown) so `docs_conformance` executes it. New `Cargo.toml` deps minimal and audited.

### Step 3. New crate `crates/plugins/oxdock-toolchain-plugin` (with CLI and facade wiring)
Files: new `Cargo.toml`, `src/lib.rs`, `src/funcs.rs`, `src/provision.rs`, `src/build.rs`, `src/targets.rs`, `src/fingerprint.rs` (or inside `build.rs`), `.oxdock/template/...`, `tests/integration/toolchain.rs` plus `tests/integration.rs` shim. Edit root `Cargo.toml` members plus `workspace.dependencies`, plus `oxdock-cli/Cargo.toml`, `oxdock/Cargo.toml`, `oxdock-cli/src/lib.rs`.

- `Cargo.toml`: mirror `oxdock-ssh-plugin` shape (inherits workspace package keys, `lints.workspace = true`, deps `*.workspace = true`). Deps: `oxdock-core`, `oxdock-fs`, `oxdock-func-macro`, `oxdock-process`, `oxdock-net-plugin` (NET DSL surface), plus pure-Rust archive and hash decode crates for verify and unpack (for example `tar`, `flate2-rust` backend, `sha2` which is already a workspace dep). No system tools, no brew, no direct `tempfile` (use `oxdock-fs` tempdir guard). Keep deps minimal and audited.
- `src/lib.rs`: `pub fn module() -> HostModule<DefaultProcessManager>` plus generic `module_with::<P: ProcessManager>()`, mirroring ssh plugin so tests bind mock transports. Composition root registers NET plus TOOLCHAIN together so one script can `IMPORT [STD, NET, TOOLCHAIN]`.
- `src/funcs.rs`: `TOOLCHAIN_*` host funcs:
  - `TOOLCHAIN_ENSURE(target_triple) -> MAP`: default triple is host, ensure cached toolchain under `<cache>/toolchain/`, return `{ cargo, rustc, sysroot, triple }` paths under the toolchain cache.
  - `TOOLCHAIN_FETCH_SOURCE(local_manifest_hint) -> MAP` (v1 local bundle): snapshot the local source tree into `<cache>/toolchain/src/local-<hash>/` via guarded COPY through `WorkspaceFs` (never writes into the local tree), return `{ manifest_dir }` pointing inside cache. Pinned tarball or `COPY_GIT` rev fetch is follow-up, not v1.
  - `TOOLCHAIN_BUILD(target_triple, manifest_dir, features, { profile }) -> MAP`: `manifest_dir` must be inside the cache guard (assert, never local tree or `SYSTEM`). `profile` defaults to `release` with explicit `dev` opt-in. Fingerprint covers source hash plus features plus profile plus flags plus toolchain versions. Rebuild only when stale into `<cache>/toolchain/target/<triple>/`. Return `{ binary, profile, releasable, metadata }` in cache.
- `src/provision.rs`: DSL-first toolchain bootstrap. Resolve triple, drive Rust standalone tarball downloads from `static.rust-lang.org/dist` through the NET plugin DSL funcs into the toolchain cache group, then sha256 verify and unpack with toolchain-side pure-Rust decoders. Never shells out to host curl, tar, sh, brew, cc, or system cargo and rustc. Never opens its own sockets around the NET module. Never reads the local repo as toolchain source and never writes into it.
- `src/build.rs`: OxDock-driven compile isolated to cache. Builds `Vec<Step>` via `oxdock!` internally (`MKDIR` in cache guard, `ENV` with `#var` injection for triple and paths, `RUN` invoking only cached `cargo` and `rustc` bins with `--manifest-path` pointing into cache and `--target-dir` inside cache, `ASSERT` on binary existence in cache), executed through `Engine::run_steps_on` with `default_process_manager()` rooted at cache guard. Auto-provisioning: before spawning `cargo build`, check for `rustc` and `cargo` under `<cache>/toolchain/dist/<triple>/bin/`; when missing, invoke `provision_toolchain(target_triple)` automatically so `TOOLCHAIN_BUILD` never fails purely because `TOOLCHAIN_ENSURE` was not called first.
- Workspace composition roots (prevents orphan-crate `UnknownCommand`): in `oxdock-cli/Cargo.toml` add `oxdock-toolchain-plugin = { workspace = true, optional = true }` with a `toolchain = ["net", "dep:oxdock-toolchain-plugin"]` entry in `[features]`; in `oxdock/Cargo.toml` add `toolchain = ["cli", "net", "oxdock-cli/toolchain"]`; in `oxdock-cli/src/lib.rs` register inside `cli_host_modules_with` behind the feature flag (for example `#[cfg(feature = "toolchain")] modules.push(oxdock_toolchain_plugin::module());`).
- `src/targets.rs`: triple table for on-demand targets (host first, then linux x86_64 and aarch64 musl-static, macOS, Windows). Unknown arch is a hard error, never a guess. Portable linking: cache a portable linker alongside Rust (zig tarball, same cache group and verify flow) so Linux needs no cc or headers. Cargo config generated into the build points at cached bins only. MSVC weight is an explicit error, not silent fallback.
- Release-grade bar: release profile by default (`--release`, panic, LTO, strip, codegen settings pinned in fingerprint), version stamp from the bundled source flowing into the binary so `oxdock --version` agrees by construction, static musl on Linux, artifact metadata (triple, profile, features, source hash, toolchain versions) returned alongside `{ binary }` and asserted in tests. Dev opt-in: no LTO, no strip, debug info kept, incremental allowed, still isolated to cache and zero host deps, marked `releasable=false` on a distinct fingerprint key so dev never poisons release.
- Guardrails: no workspace-wide clippy overrides, localized `#[allow]` on specific items only. No `_`-prefixed params. No `std::cfg` or `cfg!(miri)` in implementation outside allowed sys crates. Real network and toolchain funcs error under isolation; tests use mock or synthetic managers with `#[cfg_attr(miri, ignore = "...")]` plus reason. No em dashes in comments or docs.

- Add `toolchain_function_reference` and `toolchain_type_reference` outputs to `docs-gen.json`, wire `REFRESH_GENERATED` writes in `docs-gen/src/lib.rs`, add `oxdock_toolchain_plugin::module()` to `plugin_docs()` in `host.rs`.

Every multi-stanza `oxdock` fence carries `#` sentence comments per stanza, `IMPORT` at top, blank-line separated stanzas, and assertions that prove the adjacent claim.
