### 2. Migrate interactive-shell spawning into `oxdock-process`
Files: `crates/sys/oxdock-process/src/shell.rs` (extend), `oxdock-cli/src/lib.rs`.

In `oxdock-process/src/shell.rs` add:
- `pub fn spawn_interactive_shell(cwd: &GuardedPath, workspace_root: &GuardedPath, banner: &str) -> Result<()>`
  - **Unix branch**: `CommandBuilder::new(shell_program())` + `current_dir(cwd)`.
    - **Injection hardening (review fix)**: do NOT interpolate `banner`/shell path into the `-c` string (paths with spaces break quoting; `%` corrupts `printf`). Instead set `cmd.env("OXDOCK_BANNER", banner)` and build the script as a fixed literal: `printf '%s\n' "$OXDOCK_BANNER"; exec "$1"`, passing the shell program as positional: `.arg("-c").arg(SCRIPT).arg("sh").arg(shell_program())` (so `$0="sh"`, `$1=<shell path>`).
    - TTY reattach via `UnguardedPath::new("/dev/tty")` + `PathResolver::new(workspace_root...)` + `open_file_unguarded` inside `#[cfg(not(miri))]` (**this is why `workspace_root` stays in the signature** — it is consumed here).
    - Then `status()` + bail on failure. Under Miri, `CommandBuilder::status()`'s existing `#[cfg(miri)]` synthetic backend handles execution — no new early-return guard (a silent `Ok(())` would mask failures; Windows `spawn()` already bails cleanly under Miri).
  - **Windows branch**: move `escape_for_cmd` / `windows_banner_command` helpers here too (command-construction concerns); `cmd /C start "oxdock shell" cmd /K <banner_cmd>` with `command_path(cwd)` normalization, fire-and-forget `spawn()`.
  - **Other platforms**: bail as today.
- Extend `CommandSnapshot` to record env vars (ordered pairs) added via `CommandBuilder::env`, so tests can assert `OXDOCK_BANNER` was passed.
- Keep the existing command-hook pattern by moving it here: `SHELL_CMD_HOOK` thread_local + `try_shell_command_hook`, all under `#[cfg(test)]` (crate-internal only — **not** feature-gated publicly; `oxdock-process` is a published crate and a public mock hook would pollute its API).
- Port the two CLI tests into `shell.rs` tests: adapted to call `spawn_interactive_shell(cwd, workspace_root, "banner")`; update unix assertions for the new argv shape (script literal contains `$OXDOCK_BANNER` and `"$1"`, trailing positional equals `shell_program()`) and assert `OXDOCK_BANNER` in the captured snapshot env.

In `oxdock-cli/src/lib.rs`:
- Replace the body of local `run_shell` with a thin delegate: `oxdock_process::spawn_interactive_shell(cwd, workspace_root, &shell_banner(cwd, workspace_root))`.
- Keep `shell_banner()` in the CLI (presentation concern: `CARGO_PKG_NAME`, display paths, indoc text).
- Signature stays `(fn(&GuardedPath, &GuardedPath) -> Result<()>)` so `execute_with_shell_runner(opts, workspace_root, run_shell, true)` (lib.rs:75) is untouched.
- Remove migrated code: unix/windows branches, `escape_for_cmd`, `windows_banner_command`, hook plumbing, and the two moved tests. Keep the existing CLI-level test asserting the runner closure gets invoked (~line 505).

Dependency direction already permits this: `oxdock-process` depends on `oxdock-fs`.

### 3. Rework `tree_shell` example
File: `oxdock-cli/examples/tree_shell.rs`.
- Parse argv for `--shell` (default false), matching the doc-comment promise.
- Write `SCRIPT` to `<temp>/script.ox` via `PathResolver`, build `Options { script: ScriptSource::Path(script_path), shell }`, and run through `oxdock_cli::execute(...)` so `--shell` genuinely drops into the demo workspace.
