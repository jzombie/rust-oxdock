### Thread B: Generic pipeline + profile globals + URL JSON/TOML import
Goal: profile repo holds master globals JSON and shared fragments; any repo consumes them through OxDock docs pipeline with NET fetch. Unblock is LOAD_JSON/LOAD_TOML from URL (today file-only via `GuardedPath::resolve_read` + `read_file` in `crates/oxdock-core/src/exec/args.rs:795-847`, exposed as `LOAD_JSON`/`LOAD_TOML` in `crates/oxdock-core/src/exec/native.rs:535-548`; NET plugin today is TCP/virtual-endpoint pumps only, no HTTP client).
Recommended approach in order:
1. New URL import primitives (core, behind NET-gated behavior): `LOAD_JSON_URL(url: STRING)` and `LOAD_TOML_URL(url: STRING)` reusing `load_json_value`/`load_toml_value` in `args.rs`. Semantics: https-only allowlist (profile raw.githubusercontent URLs), redirect limit, timeout, offline fallback error, no sandbox WRITE (in-memory only), `--offline` equivalent fails closed. Alternative considered (extend LOAD_JSON to auto-detect URL) rejected: keeps guarded-file vs network audit paths distinct for clippy `disallowed_methods` and Miri. New tests in `oxdock-logic-tests` with mocked fetch plus parity harness notes.
2. Minimal docs-gen generalization (no full crate split yet): allow `docs-gen.json: global_values` as string-or-list with merge precedence (master globals URL/file cached to `target/oxdock-docs/` then local overrides win); add `FETCH_GLOBALS` pre-step in `crates/docs-gen/src/lib.rs` before `BUILD_MANIFEST` using new URL loaders + `WRITE` cache; keep `EXPAND_FRAGMENT` scope (`host.rs:133-162`) as `$docs_global/$docs_ctx/env:CRATE_VERSION` so fetched master JSON slots in with zero template churn.
