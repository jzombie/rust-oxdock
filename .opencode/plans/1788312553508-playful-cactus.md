# Architecture: Optimal Declarative Model

Converts Plan v8 from per-command file layout to a single `declare_commands!` macro in the parser crate.

---

## Problem

Command metadata and lowering are scattered across `oxdock-core/src/commands.rs` (22 structs, 1254 lines). Adding a command requires: (1) a new struct + `CommandSpec` impl in `commands.rs`, (2) a variant in `StepKind` in `ast.rs`, (3) a handler in `handlers.rs`, (4) a match arm in `define_pipeline!` invocation. The goal is **single-site declaration** for everything except execution.

---

## Architecture Overview

```
oxdock-parser                               oxdock-core
┌──────────────────────────────┐            ┌──────────────────────────┐
│ commands.rs                  │            │ pipeline.rs              │
│                              │            │                          │
│ declare_commands! {          │            │ define_pipeline! {       │
│   structural {               │            │   StepKind::Write { .. } │
│     WithIo, For, If, ...    │            │     => handlers::write,  │
│   }                          │            │   ...                    │
│   Write => { variant, ... }  │            │ }                        │
│   Workdir => { variant, .. } │            │                          │
│   ...                        │            │ Generates:               │
│ }                            │◄───────────│   execute_command()      │
│                              │            │                          │
│ Generates:                   │            │ exec/handlers.rs         │
│   pub enum StepKind          │            │ (cx, step) uniformly     │
│   fn lower_command()         │            └──────────────────────────┘
│   fn all_metadata()          │
│                              │
│ strip_flags, CommandMeta,    │
│ ArgSpec, FlagSpec, etc.      │
└──────────────────────────────┘
```

## Component Changes Matrix

| Component | Plan v8 Location | Declarative Location | Change |
|---|---|---|---|
| **AST Enum (`StepKind`)** | `oxdock-parser/src/ast.rs` | `oxdock-parser/src/commands.rs` | Auto-generated by `declare_commands!` |
| **Command Metadata + Lowering** | 22 structs in `oxdock-core/src/commands.rs` | `oxdock-parser/src/commands.rs` | Consolidated into `declare_commands!` blocks |
| **Lowering Dispatch** | Generated in `oxdock-core/src/pipeline.rs` | `oxdock-parser/src/commands.rs` | Generated directly in parser crate |
| **Execution Handlers** | `oxdock-core/src/exec/handlers.rs` | `oxdock-core/src/exec/handlers.rs` | Retained (uniform `(cx, step)`) |
| **Execution Dispatch** | `oxdock-core/src/pipeline.rs` | `oxdock-core/src/pipeline.rs` | Simplified: only variant → handler mapping |
| **In-Process Test Harness** | `oxdock-logic-tests/build.rs` | `oxdock-logic-tests/build.rs` | Retained (Phase 6 from Plan v8) |

## Step-by-Step Plan

### 1. Create `crates/oxdock-parser/src/commands.rs`

New file. Houses the `declare_commands!` macro and its invocation. The macro generates:

- `pub enum StepKind` — command variants from declarations + structural variants (`WithIo`, `WithIoBlock`, `For`, `If`, `Assign`)
- `pub fn lower_command(name: &str, raw_args: Vec<Arg>) -> Result<StepKind>` — flag stripping + `CommandSpec::lower` dispatch
- `pub fn all_metadata() -> Vec<CommandMeta>` — collects metadata from all declarations

Each declaration block specifies:

```rust
declare_commands! {
    // ── Structural variants (always present, not dispatched by name) ──
    structural {
        WithIo { bindings: Vec<IoBinding>, cmd: Box<StepKind> },
        WithIoBlock { bindings: Vec<IoBinding> },
        For { key_var: Option<String>, var: String, in_expr: Expr, body: Vec<Step> },
        If { cond: Box<Expr>, then_body: Vec<Step>, else_ifs: Vec<(Box<Expr>, Vec<Step>)>, else_body: Option<Vec<Step>> },
        Assign { var: String, expr: Expr },
    }

    // ── Command variants (dispatched by name via lower_command) ──
    Write => {
        name: "WRITE",
        variant: Write { path: Arg, contents: Option<Arg> },
        syntax: "WRITE <path> [<contents>]",
        summary: "Writes contents to a file.",
        description: indoc! {"
            Writes contents to a file, replacing any existing contents.
            Creates parent directories on demand. Without a contents
            argument it consumes stdin.
        "},
        args: &[
            ArgSpec { name: "path", arg_type: "Path", description: "File to write", io: IoDirection::Write, index: 0, required: true, fallback_stream: None },
            ArgSpec { name: "contents", arg_type: "String", description: "Content to write", io: IoDirection::Read, index: 1, required: false, fallback_stream: Some(Stream::Stdin) },
        ],
        flags: &[],
        default_output: None,
        examples: &[
            Example {
                name: "Direct write",
                fence_meta: None,
                code: indoc! {r#"
                    WRITE dist/hello.txt "Built with OxDock"
                    ASSERT_FILE dist/hello.txt "Built with OxDock"
                "#},
            },
        ],
        lower: |_flags, args| {
            let mut iter = args.into_iter();
            let path = iter.next().ok_or_else(|| ::anyhow::anyhow!("WRITE requires path"))?;
            let contents = iter.next();
            Ok(StepKind::Write { path, contents })
        }
    },

    Workdir => {
        name: "WORKDIR",
        variant: Workdir(Arg),
        syntax: "WORKDIR <path>",
        summary: "Change the working directory for subsequent steps.",
        description: "Sets the current working directory. Relative paths resolve against the current root.",
        args: &[ ArgSpec { name: "path", arg_type: "Path", description: "Directory to change to", io: IoDirection::Write, index: 0, required: true, fallback_stream: None } ],
        flags: &[],
        default_output: None,
        examples: &[
            Example {
                name: "change working directory",
                fence_meta: None,
                code: indoc! {r#"
                    WORKDIR project/src
                    WRITE generated.txt generated-under-workdir
                "#},
            },
        ],
        lower: |_flags, args| Ok(StepKind::Workdir(args.into_iter().next().ok_or_else(|| ::anyhow::anyhow!("WORKDIR requires path"))?))
    },

    InheritEnv => {
        name: "INHERIT_ENV",
        variant: InheritEnv { keys: Vec<String> },
        syntax: "INHERIT_ENV <key>...",
        summary: "Inherits environment variables from the host process.",
        description: "Imports specified environment variables from host OS into step context.",
        args: &[],
        flags: &[],
        default_output: None,
        examples: &[],
        lower: |_flags, args| {
            let keys = args.into_iter().map(|a| a.as_str().to_string()).collect();
            Ok(StepKind::InheritEnv { keys })
        }
    },

    // ... remaining 20 commands follow same pattern
}
```

**The macro expands to a single `pub enum StepKind`** containing both structural and command variants, plus `lower_command` and `all_metadata`:

```rust
// Generated output (single contiguous enum):
pub enum StepKind {
    // Command variants from `Name => { variant: ... }` blocks
    Workdir(Arg),
    Workspace(WorkspaceTarget),
    Env { key: String, value: Arg },
    InheritEnv { keys: Vec<String> },
    Run(Arg),
    Echo(Arg),
    // ... all 22 command variants

    // Structural variants from `structural { ... }` block
    WithIo { bindings: Vec<IoBinding>, cmd: Box<StepKind> },
    WithIoBlock { bindings: Vec<IoBinding> },
    For { key_var: Option<String>, var: String, in_expr: Expr, body: Vec<Step> },
    If { cond: Box<Expr>, then_body: Vec<Step>, else_ifs: Vec<(Box<Expr>, Vec<Step>)>, else_body: Option<Vec<Step>> },
    Assign { var: String, expr: Expr },
}

// lower_command dispatches command names only (structural variants are not name-dispatched)
pub fn lower_command(name: &str, raw_args: Vec<Arg>) -> Result<StepKind> { ... }

// all_metadata returns only command metadata (structural variants have no metadata)
pub fn all_metadata() -> Vec<CommandMeta> { ... }
```

**`lower_command` generation logic:**

```rust
pub fn lower_command(name: &str, raw_args: Vec<Arg>) -> Result<StepKind> {
    match name {
        $(
            s if s == $name => {
                let meta = /* metadata for this command */;
                let (flags, positional) = strip_flags(raw_args, &meta)?;
                let lower_fn: fn(Vec<(String, Arg)>, Vec<Arg>) -> Result<StepKind> = $lower;
                lower_fn(flags, positional)
            }
        )*
        _ => bail!("unknown command: {name}"),
    }
}
```

**`all_metadata` generation logic:**

```rust
pub fn all_metadata() -> Vec<CommandMeta> {
    vec![
        $( CommandMeta {
            name: $name,
            syntax: $syntax,
            summary: $summary,
            description: $description,
            args: $args,
            flags: $flags,
            default_output: $default_output,
            examples: $examples,
        }, )*
    ]
}
```

### 2. Simplify `crates/oxdock-core/src/pipeline.rs`

Strip lowering dispatch and metadata registry. `define_pipeline!` becomes execution-only:

```rust
#[macro_export]
macro_rules! define_pipeline {
    ( $( $variant:pat => $handler:path ),* $(,)? ) => {
        pub fn execute_command<P: $crate::ProcessManager>(
            cx: &mut $crate::exec::StepCtx<'_, P>,
            step: &$crate::StepKind,
        ) -> ::anyhow::Result<()> {
            match step {
                $( $variant => $handler(cx, step), )*
                $crate::StepKind::WithIo { .. } => $crate::exec::dispatch_with_io(cx, step),
                $crate::StepKind::WithIoBlock { .. } => $crate::exec::dispatch_with_io_block(cx, step),
                $crate::StepKind::InheritEnv { .. } => $crate::exec::dispatch_inherit_env(cx, step),
                $crate::StepKind::For { .. } => $crate::exec::dispatch_for_loop(cx, step),
                $crate::StepKind::If { .. } => $crate::exec::dispatch_if_then(cx, step),
                $crate::StepKind::Assign { .. } => $crate::exec::dispatch_assign(cx, step),
            }
        }
    };
}
```

**Invocation in `oxdock-core/src/lib.rs`:**

```rust
define_pipeline! {
    StepKind::Run(..) => exec::dispatch_run,
    StepKind::RunBg(..) => exec::dispatch_run_bg,
    StepKind::Echo(..) => exec::dispatch_echo,
    StepKind::Workdir(..) => exec::dispatch_workdir,
    StepKind::Workspace(..) => exec::dispatch_workspace,
    StepKind::Env { .. } => exec::dispatch_env,
    StepKind::Copy { .. } => exec::dispatch_copy,
    StepKind::CopyGit { .. } => exec::dispatch_copy_git,
    StepKind::Symlink { .. } => exec::dispatch_symlink,
    StepKind::Mkdir(..) => exec::dispatch_mkdir,
    StepKind::Ls(..) => exec::dispatch_ls,
    StepKind::Cwd => exec::dispatch_cwd,
    StepKind::Read(..) => exec::dispatch_read,
    StepKind::Write { .. } => exec::dispatch_write,
    StepKind::Append { .. } => exec::dispatch_append,
    StepKind::Expand { .. } => exec::dispatch_expand,
    StepKind::AssertFile { .. } => exec::dispatch_assert_file,
    StepKind::AssertDir(..) => exec::dispatch_assert_dir,
    StepKind::AssertAbsent(..) => exec::dispatch_assert_absent,
    StepKind::AssertStdout(..) => exec::dispatch_assert_stdout,
    StepKind::HashSha256 { .. } => exec::dispatch_hash_sha256,
    StepKind::Exit(..) => exec::dispatch_exit,
}
```

No more `(StepKindVariant, CommandType)` tuples — just variant → handler.

### 3. Delete `crates/oxdock-core/src/commands.rs`

The entire 1254-line file with 22 `CommandSpec` impl blocks is replaced by `declare_commands!` in the parser crate. Delete the file and remove `pub mod commands;` / `pub use commands::*;` from `oxdock-core/src/lib.rs`.

### 4. Update `oxdock-parser/src/lib.rs`

Re-export generated items:

```rust
pub mod commands;  // declare_commands! invocation
pub use commands::{StepKind, lower_command, all_metadata};

// Keep existing re-exports
pub use command::{ArgSpec, CommandMeta, Example, FlagSpec, FlagValueType, IoDirection, Stream};
pub use strip_flags::strip_flags;
```

### 5. Refactor `crates/oxdock-parser/src/ast.rs`

Remove the hand-written `StepKind` enum from `ast.rs` (now auto-generated by `declare_commands!` in `commands.rs`).

**`Step` stays in `ast.rs`.** It imports `StepKind` from `commands.rs`:

```rust
// In crates/oxdock-parser/src/ast.rs
use crate::commands::StepKind;

pub struct Step {
    pub guard: Option<GuardExpr>,
    pub kind: StepKind,
    pub scope_enter: usize,
    pub scope_exit: usize,
}
```

The `Display` impl for `Step` stays in `ast.rs` (it uses `GuardExpr` which is local, and `StepKind` which is imported). The `Display` impl for `StepKind` moves to `commands.rs` (it uses `Arg`, `IoBinding`, etc. which are imported from `ast.rs`).

Retain in `ast.rs`: `Step`, `Arg`, `Expr`, `IoBinding`, `WorkspaceTarget`, `GuardExpr`, `TemplateString`, `Command`, `PlatformGuard`, `Guard`, `IoStream`, `Value`, `CompareOp`, `LogicalOp`, plus all `Display` impls for non-`StepKind` types.

Re-export `StepKind` from `ast.rs` for backward compatibility:
```rust
pub use crate::commands::StepKind;
```

**Impact:** Files importing `Step` or `StepKind` from `oxdock_parser::ast` will continue to work via re-export:
- `oxdock-core/src/exec/*.rs`
- `oxdock-parser/src/parser.rs`
- `oxdock-parser/src/macro_input.rs`
- `oxdock-logic-tests/src/lib.rs`
- `crates/docs-gen/src/*`

### 7. Add Tests for Registry and Examples

Add unit tests in `crates/oxdock-parser/src/commands.rs`:

- **`lower_command` tests:** Verify each command name dispatches correctly, flag stripping works, unknown commands return error
- **`all_metadata` tests:** Verify all 22 commands present, metadata fields non-empty
- **Example execution tests:** Parse and execute each `Example::code` through `parse_script` + `lower_command` to verify examples are valid scripts

### 6. Retain In-Process Test Harness (Phase 6)

Keep Phase 6 of Plan v8 intact. `build.rs` consumes `oxdock_parser::lower_command` (now generated by `declare_commands!`) to produce in-process `#[test]` functions.

## Implementation Phases

### Phase 1: `declare_commands!` Macro + Parser Registry
- Create `crates/oxdock-parser/src/commands.rs` with `declare_commands!` macro definition
- Keep `CommandSpec` trait and types in `command.rs` (re-exported by `lib.rs`)
- Write `declare_commands!` invocation with `structural { ... }` block (5 variants) + all 22 command declarations
- Macro generates: `pub enum StepKind`, `lower_command`, `all_metadata`
- Remove `StepKind` enum from `ast.rs`; add `use crate::commands::StepKind;` to `ast.rs` so `Step` can reference it
- Re-export `StepKind` from `ast.rs` for backward compatibility
- Move `Display` impl for `StepKind` to `commands.rs`
- Lowering closures use `args.into_iter().next().ok_or_else(|| anyhow::anyhow!(...))` (not `args.remove(0).ok_or(...)`)
- Array literals in metadata use `&[...]` slices (not bare `[...]`)
- Verify: `cargo build -p oxdock-parser`

### Phase 2: Simplify Pipeline
- Simplify `define_pipeline!` in `oxdock-core/src/pipeline.rs` to execution-only with `(cx, step)` uniformly
- Replace `with_io(cx, 0, 0, ...)` with `dispatch_with_io(cx, step)` helpers
- Update invocation in `oxdock-core/src/lib.rs`
- Remove `pub mod commands; pub use commands::*;` from `oxdock-core/src/lib.rs`
- Delete `crates/oxdock-core/src/commands.rs`
- Verify: `cargo build -p oxdock-core`

### Phase 3: Fix Imports Across Workspace
- Update `oxdock-parser/src/parser.rs`: `use crate::ast::{... Step, StepKind}` → `use crate::{Step, StepKind}`
- Update `oxdock-parser/src/macro_input.rs`: `use super::{Command, Step, ...}` → `use crate::{Step, ...}`
- Update `oxdock-core/src/exec/*.rs` if needed
- Verify: `cargo test --workspace --tests`

### Phase 4: Add Registry and Example Tests
- Add unit tests for `lower_command` (valid commands, flag stripping, unknown command error)
- Add unit tests for `all_metadata` (all 22 commands present)
- Add tests that parse and execute each `Example::code` through `parse_script` + `lower_command`
- Verify: `cargo test -p oxdock-parser`

### Phase 5: In-Process Test Harness (Phase 6 from Plan v8)
- `build.rs` consumes `oxdock_parser::lower_command` directly (generated by `declare_commands!`)
- Update `build.rs` template to use `oxdock_parser::lower_command` instead of `oxdock_core::lower_command`
- Retain all other Phase 6 details unchanged
- Verify: `cargo test -p oxdock-logic-tests -- command_cases`
