## Phase 4: Implement `oxdock!` Proc-Macro

### 4a. Interpolation Design — `#var` (hash + identifier)

**Why `#` not `$`**: The DSL already uses `$variable` for LET/FOR bindings. Using `$` for Rust host interpolation would create an unresolvable namespace collision. `#` is the correct sigil — it mirrors `quote!`'s interpolation convention and keeps host and DSL contexts strictly separated.

**The token substitution pipeline**:

The `oxdock!` macro receives a braced token stream like:
```rust
oxdock! {
    #inherit_step
    #init_step
    LET $sections = GLOB('#sec_dir/*.md')
    FOR $f IN $sections {
        WITH_IO [stdout=pipe:sec] READ $f
        WITH_IO [stdin=pipe:sec] APPEND '#out'
        APPEND '#out' "\n"
    }
}
```

Pipeline steps:
1. **Walk the TokenStream**: Collect all `#ident` pairs (Punct `#` + Ident). Assign each a unique index. Record the mapping: `(Ident, usize)`.
2. **Build safe DSL text**: Walk again, replacing each `#ident` with a synthetic placeholder string `__OXDOCK_INJECT_<N>__` that the Pest grammar accepts as a valid bare argument (alphanumeric + underscores).
3. **Parse**: Feed the sanitized DSL text to `parse_script()` → `Vec<Step>`. The steps contain `__OXDOCK_INJECT_N__` placeholder strings in `Arg::Template` positions.
4. **Emit reconstruction code**: Walk each `Step` and emit `quote!` code that constructs the AST:
   - `Arg` containing a placeholder → emit `Arg::Literal(#var_name.to_string())` — **never** `Arg::Template`, to prevent host strings from being re-evaluated as DSL templates
   - `Arg` without a placeholder → emit as literal string: `Arg::Template(TemplateString("literal".into()))`
   - `Expr::Literal(Value::String(s))` containing a placeholder → emit `Expr::Literal(Value::String(#var_name.to_string()))`
   - All other AST fields (guards, scope counts, StepKind variants, Expr variants) → emit as literal values
5. **Return**: The emitted code builds `Vec<Step>` at runtime, with Rust variable references wired by the compiler.

**Key constraint**: The `#` sigil must be stripped before Pest parsing. Pest does not understand `#` as part of DSL syntax. The macro walks the token stream *before* stringification, replacing `#ident` with safe placeholders, so the stringified text is always valid Pest input.

### 4b. Implementation in `oxdock-macros/src/lib.rs`

```rust
/// Runtime AST construction macro with `#var` interpolation.
///
/// Accepts the same DSL syntax as `oxdock_embed!`'s `script:` block,
/// but returns `Vec<oxdock_parser::Step>` instead of embedding files.
///
/// Use `#var` to inject Rust variables (must implement `Display`/`ToString`).
/// DSL variables (`$var` in LET/FOR) are distinct and unaffected.
#[proc_macro]
pub fn oxdock(input: TokenStream) -> TokenStream {
    expand_oxdock(input).unwrap_or_else(|e| syn::Error::to_compile_error(e).into())
}
```

**Internal functions**:

`fn expand_oxdock(input: TokenStream) -> Result<TokenStream>`:
1. Parse input as a braced `TokenStream2` (reuse `syn::braced!`)
2. Call `collect_hash_interpolations(ts)` → `(Vec<(Ident, usize)>, TokenStream2)` — walks the stream, returns the collected idents + a modified stream with `#ident` replaced by placeholder ident tokens
3. Build DSL text from the modified stream via `script_from_braced_tokens()`
4. Replace each `__OXDOCK_INJECT_N__` with a valid bare-word token the parser accepts
5. Call `parse_script(&dsl_text)` → `Vec<Step>`
6. Call `emit_steps_with_interpolation(steps, &interpolations)` → `TokenStream2`
7. Wrap in `quote!({ use oxdock_parser::{Arg, TemplateString, Step, StepKind, ...}; vec![#(#steps),*] })`

`fn collect_hash_interpolations(ts: TokenStream2) -> Result<(Vec<(Ident, usize)>, TokenStream2)>`:
- Walk tokens. When encountering Punct `#` followed by Ident, record `(ident, idx)` and emit a placeholder ident `__OXDOCK_INJECT_0__` instead. All other tokens pass through unchanged.

`fn emit_steps_with_interpolation(steps: &[Step], interp: &[(Ident, usize)]) -> Result<Vec<TokenStream2>>`:

Recursively walks every AST node type. Two rules govern placeholder resolution:

**Rule 1 — `Arg` emission (anti double-evaluation):**
When an `Arg` (either `Arg::Literal` or `Arg::Template`) contains an `__OXDOCK_INJECT_N__` placeholder, emit it as `Arg::Literal(#var_name.to_string())` — **never** `Arg::Template`. Host-injected strings must bypass runtime `$variable` and `{{ env:KEY }}` expansion entirely. Wrapping in `TemplateString` would re-inject host values into the DSL evaluation pipeline, causing silent breakage if the host string contains `$` or `{{`.

**Rule 2 — `Expr` / `Value` traversal:**
`GLOB(#glob_pattern)` produces `Expr::Call { name: "GLOB", args: [Expr::Literal(Value::String("__OXDOCK_INJECT_N__"))] }`, not an `Arg`. The emission walk must pattern-match against:
- `Expr::Literal(Value::String(s))` — if `s` contains a placeholder, emit `Expr::Literal(Value::String(#var_name.to_string()))`
- `Expr::Var(s)` — same check
- `Expr::List(items)` — recurse into each item
- `Expr::Call { name, args }` — recurse into each arg

**Recursive traversal targets:**
- `Step` → `guard`, `kind`, `scope_enter`, `scope_exit`
- `StepKind` variants containing `Arg` or `Expr`:
  - `Workdir(Arg)`, `Run(Arg)`, `Echo(Arg)`, `RunBg(Arg)`, `Mkdir(Arg)`, `Ls(Option<Arg>)`, `Read(Option<Arg>)`, `AssertDir(Arg)`, `AssertAbsent(Arg)`, `AssertStdout(Arg)`
  - `Env { key, value: Arg }` — resolve `value`
  - `Copy { from, to }`, `Symlink { from, to }` — resolve both `Arg`s
  - `Write { path, contents }`, `RawWrite { path, contents }`, `Append { path, contents }` — resolve both
  - `Expand { path, overrides }` — resolve `path` and each override value
  - `AssertFile { path, contents, .. }` — resolve `path` and `contents`
  - `CopyGit { rev, from, to }` — resolve all three
  - `HashSha256 { path }` — resolve `path`
  - `WithIo { cmd, .. }` — recurse into `Box<StepKind>`
  - `For { in_expr, body, .. }` — resolve `in_expr` (an `Expr`), recurse into `body` (a `Vec<Step>`)
  - `Assign { expr, .. }` — resolve `expr` (an `Expr`)

### 5b. Delete `DocSpec` — invert control

`assemble_doc` no longer owns the conditional structural logic (template selection, INHERIT_ENV keys). The callers do — they have the statically known values at their call site. `assemble_doc` receives pre-built `Vec<Step>` and appends the core loop.

**Delete** `crates/docs-gen/src/doc_runner.rs` `DocSpec` struct entirely.

### 5c. Rewrite `crates/docs-gen/src/doc_runner.rs`

```rust
use anyhow::Result;
use oxdock_core::{ExecIo, run_steps_with_context_result_with_io};
use oxdock_fs::GuardedPath;
use oxdock_macros::oxdock;
use oxdock_parser::Step;
use std::path::Path;

pub fn assemble_doc(
    repo_root: &Path,
    mut steps: Vec<Step>,
    sections_dir: &Path,
    output_path: &Path,
    env: ExecIo,
) -> Result<()> {
    let out_str = output_path.display().to_string();
    let glob_pattern = format!("{}/*.md", sections_dir.display());

    let core_steps = oxdock! {
        LET $sections = GLOB(#glob_pattern)
        FOR $f IN $sections {
            WITH_IO [stdout=pipe:sec] READ $f
            WITH_IO [stdin=pipe:sec] APPEND #out_str
            APPEND #out_str "\n"
        }
    };

    steps.extend(core_steps);

    let root = GuardedPath::new_root(repo_root)?;
    run_steps_with_context_result_with_io(&root, &root, &steps, env)?;
    Ok(())
}
```

**What's eliminated**: `DocSpec`, `parse_script()`, all `format!` calls in doc_runner, manual string composition.

### 5d. Rewrite `crates/docs-gen/src/crate_readme.rs`

Callers build init steps via `oxdock!` with native DSL — conditional logic (template vs no-template) lives here where the values are known:

```rust
use anyhow::Result;
use oxdock_core::ExecIo;
use oxdock_macros::oxdock;
use std::path::{Path, PathBuf};

use crate::doc_runner::assemble_doc;

// ... (generate_all, find_cargo_toml, parse_cargo_metadata unchanged)

fn generate_one(
    template_path: &Path,
    crate_doc_dir: &Path,
    cargo_toml: &Path,
    repo_root: &Path,
) -> Result<()> {
    let metadata = parse_cargo_metadata(cargo_toml)?;
    let out_path = cargo_toml.parent().unwrap().join("README.md");

    let mut io = ExecIo::new();
    io.insert_inherit_env("CRATE_NAME", &metadata.name);
    io.insert_inherit_env("CRATE_DESCRIPTION", &metadata.description);

    let template_str = template_path.display().to_string();
    let out_str = out_path.display().to_string();

    let init_steps = oxdock! {
        INHERIT_ENV [CRATE_NAME, CRATE_DESCRIPTION]
        WITH_IO [stdout=pipe:base] EXPAND #template_str
        WITH_IO [stdin=pipe:base] WRITE #out_str
    };

    assemble_doc(repo_root, init_steps, crate_doc_dir, &out_path, io)
}
```

### 5e. Rewrite `crates/docs-gen/src/sections.rs`

```rust
use anyhow::Result;
use oxdock_core::ExecIo;
use oxdock_macros::oxdock;
use std::path::Path;

use crate::doc_runner::assemble_doc;

pub fn assemble_readme(repo_root: &Path, output: Option<&Path>) -> Result<()> {
    let out_path = output
        .map(|p| p.to_path_buf())
        .unwrap_or_else(|| repo_root.join("README.md"));
    let sections_dir = repo_root.join("docs/sections");

    let out_str = out_path.display().to_string();

    let init_steps = oxdock! {
        RAW_WRITE #out_str ""
    };

    assemble_doc(repo_root, init_steps, &sections_dir, &out_path, ExecIo::new())
}
```
