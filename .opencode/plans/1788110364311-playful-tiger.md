# Plan: FOR-over-maps — `FOR $k, $v IN $map`

## Context

The `FOR` loop currently only iterates over `Value::List`. Iterating over `Value::Map` (returned by `LOAD_TOML`/`LOAD_JSON`) produces `"FOR loop requires a list iterable"`. This blocks native manifest-driven workflows.

**Syntax:** `FOR $k, $v IN $map { ... }` — when two variables are given, the iterable must be a `Value::Map`. `$k` gets the string key, `$v` gets the value. Single-variable `FOR $x IN $list` remains unchanged.

## Step 1: Grammar — `dsl.pest`

```pest
for_statement = { for_keyword ~ dollar_ident ~ ("," ~ dollar_ident)? ~ in_keyword ~ expr ~ block }
```

## Step 2: AST — `ast.rs`

```rust
For {
    key_var: Option<String>,  // key variable ($k) — only for map iteration
    var: String,              // value variable ($v) — always present
    in_expr: Expr,
    body: Vec<Step>,
},
```

**Variable binding order:** First `dollar_ident` after `FOR` is always the value variable when only one is given (`FOR $v IN ...`). When two are given (`FOR $k, $v IN ...`), first is key, second is value.

Update `Display for StepKind` to render `FOR $k, $v IN expr { ... }` when `key_var` is `Some`, or `FOR $v IN expr { ... }` when `None`.

## Step 3: Parser — `parser.rs`

In `parse_for_statement_from_pair`, collect both `Rule::dollar_ident` pairs. If two exist: first → `key_var = Some(...)`, second → `var = ...`. If one exists: `key_var = None`, that one → `var = ...`.

## Step 4: Handler — `handlers.rs`

Update `for_loop` signature to `key_var: Option<&str>, val_var: &str`.

Add `Value::Map` branch:
- Extract and sort keys lexicographically for deterministic iteration.
- Set both `key_var` and `val_var` in scope per iteration.
- If `key_var` is `None` and iterable is a map: error with clear message.
- If `key_var` is `Some` and iterable is a list: error with clear message.
- Reject any non-List/Map iterable with a typed error.

## Step 5: Step Dispatch — `steps.rs`

Update both `StepKind::For` match arms to destructure `key_var` and pass `key_var.as_deref()` to `handlers::for_loop`.

## Step 6: Macro Emission — `lib.rs`

Handle `Option<String>` explicitly:
```rust
let key_var_tokens = match key_var {
    Some(k) => quote! { Some(#k.to_string()) },
    None => quote! { None },
};
```

## Step 7: Tests

**Parser test** (`crates/oxdock-parser/src/lib.rs`):

```
Verify AST has `key_var: Some("k")`.

**Integration test** (`crates/oxdock-core/tests/key_path.rs`):

}
```
With a test TOML file containing a map section. Verify stdout contains expected key=value lines in sorted order.
