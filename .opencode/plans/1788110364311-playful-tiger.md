# Plan: Docker-Style Default Expansion + Delete RAW_WRITE

## Context

All strings expand by default. `\$` → literal `$`, `\{{` → literal `{{`. Delete `RAW_WRITE`.

**Escape rules:**
- `\\` → literal `\`
- `\$` → literal `$`, skips variable lookup
- `\{{` → literal `{{`, skips template expansion
- All other `$` and `{{` expand normally

**Single source of truth:** ALL backslash processing happens in one place — `expand_string` at runtime. The parser passes string contents verbatim (no escape stripping).

```rust
pub(crate) fn expand_string(input: &str, state: &ExecState) -> String {
    let mut output = String::new();
    let mut chars = input.chars().peekable();
    while let Some(c) = chars.next() {
        match c {
            '\\' => match chars.peek() {
                Some(&'\\') => { output.push('\\'); chars.next(); }
                Some(&'$') => { output.push('$'); chars.next(); }
                Some(&'n') => { output.push('\n'); chars.next(); }
                Some(&'t') => { output.push('\t'); chars.next(); }
                Some(&'r') => { output.push('\r'); chars.next(); }
                Some(&'"') => { output.push('"'); chars.next(); }
                Some(&'{') if chars.clone().nth(1) == Some('{') => {
                    output.push_str("{{"); chars.next(); chars.next();
                }
                _ => output.push('\\'),
            },
            '$' => { /* collect variable name, look up, emit value */ }
            '{' if chars.peek() == Some(&'{') => {
                chars.next();
                /* collect until }}), expand env:KEY */
            }
            _ => output.push(c),
        }
    }
    output
}
```

## Appendix: `{{ $a }}` as Unified Interpolation Syntax

### Motivation

The current model uses bare `$a` for variable interpolation inside strings (e.g., `"$a.txt"`). This creates ambiguity with dot-notation field access and forces `\$` escaping for literal dollar signs. Switching to `{{ $a }}` as the *only* interpolation trigger inside double-quoted strings solves these problems cleanly.

### Key Benefits

#### 1. Eliminates `\$` Escaping Noise

If `$` only evaluates inside `{{ ... }}`, bare `$` signs inside normal strings remain 100% literal text.

- `"Price is $5.00"` requires zero backslash escaping.
- `"jQuery $ is ready"` requires zero backslash escaping.
- Only `"{{ $price }}"` triggers variable lookup.

#### 2. Eliminates `$a.txt` Ambiguity

- **Inside expressions (`LET`, `IF`):** `$a.txt` is unambiguously an object field access on `$a`.
- **Inside strings (`WRITE`):** `"{{ $a }}.txt"` is unambiguously variable `$a` followed by literal string `.txt`.

#### 3. Maintains Variable Identifier Parity

Because script variables start with `$` everywhere else in the language (`LET $a = "notes"`, `FOR $item IN $list`), using `{{ $a }}` inside strings maintains the `$` symbol everywhere. You don't have to remember to drop the `$` when moving a variable inside a string.

### Syntax Comparison

| Scenario | Original Mixed Model | Proposed `{{ $a }}` Model |
| --- | --- | --- |
| **Local Variable String** | `"$a.txt"` | `"{{ $a }}.txt"` |
| **Env Variable String** | `"{{ env:USER }}"` | `"{{ env:USER }}"` (or `"{{ $env.USER }}"`) |
| **Literal Dollar Sign** | `"\$5.00"` | `"$5.00"` |
| **Literal Template Braces** | `"\{{ env:USER }}"` | `"\{{ env:USER }}"` |

### Implementation Notes

- **Grammar change:** Inside `message` / `run_args` / `argument` string literals, `{{ ... }}` is the *only* trigger for variable expansion. Bare `$` is literal.
- **Expression contexts** (`LET`, `IF`, `FOR ... IN`): `$a.b.c` continues to work as field access — no change needed.
- **`expand_string` update:** Remove the `$` → variable interpolation branch. `{{ }}` handles both `$var` and `env:KEY` lookups.
- **Backward compatibility:** Existing scripts using `"$var"` in strings will break — this is a deliberate breaking change. Migration: `"$var"` → `"{{ $var }}"`.

## Phase 9: Enforce `{{ $a }}` as the ONLY Interpolation Syntax

### Goal

Make `{{ $var }}` the *only* way to interpolate variables inside double-quoted strings. Bare `$var` becomes literal text. Enforce this through comprehensive tests.

### Step 1: Modify `expand_string` — Remove Bare `$` Interpolation, Enhance `{{ }}`

**File:** `crates/oxdock-core/src/exec/args.rs`

**1a. Remove bare `$` interpolation:**

In `expand_string` (line 280), remove the `'$' => { ... }` match arm (lines 330-401). Bare `$` now falls through to the `_ => output.push(c)` default, producing literal `$`.

Keep the `'\\'` arm but remove the `\$` sub-case (no longer needed — bare `$` is already literal). Keep `\{{`, `\\`, `\n`, `\t`, `\r`, `\"`.

**1b. Enhance `{{ }}` handler for `$var` scope lookup:**

The current `{{ }}` handler (lines 402-431) only looks up keys in `env`. Extend it to support `{{ $var }}` and `{{ $var.path.0 }}` by parsing the extracted `template_key` string directly — NOT by reading from `chars` (which has already advanced past `}}`).

```rust
'{' if chars.peek() == Some(&'{') => {
    chars.next(); // consume second {
    let mut template_key = String::new();
    let mut found_close = false;
    while let Some(ch) = chars.next() {
        if ch == '}' && chars.peek() == Some(&'}') {
            chars.next(); // consume second }
            found_close = true;
            break;
        }
        template_key.push(ch);
    }
    if found_close {
        let key = template_key.trim();
        if let Some(var_expr) = key.strip_prefix('$') {
            // {{ $var }} or {{ $var.path.0 }} — look up in scope chain.
            // Parse the key-path from the extracted string, NOT from chars.
            let mut parts = var_expr.split('.');
            if let Some(base_var) = parts.next() {
                let mut current = state.get_var(base_var).cloned()
                    .or_else(|| env.get(base_var).map(|v| Value::String(v.clone())));
                for part in parts {
                    current = match current {
                        Some(Value::Map(map)) => map.get(part).cloned(),
                        Some(Value::List(list)) => {
                            part.parse::<usize>().ok()
                                .and_then(|idx| list.get(idx).cloned())
                        }
                        _ => None,
                    };
                    if current.is_none() { break; }
                }
                if let Some(v) = current {
                    output.push_str(&format_value_for_string(&v));
                }
                // Missing → emit empty (matches StreamingExpand)
            }
        } else {
            // {{ env:KEY }} or {{ bare_key }} — look up in env
            let env_key = key
                .strip_prefix("env:")
                .or_else(|| key.strip_prefix("script_env:"))
                .unwrap_or(key);
            if let Some(val) = env.get(env_key) {
                output.push_str(val);
            }
            // Missing → emit empty
        }
    } else {
        output.push_str("{{");
        output.push_str(&template_key);
    }
}
```

**Why not read from `chars`:** The `while` loop that collects `template_key` advances `chars` past the entire `}}` delimiter. After the loop, `chars` points to the character *after* `}}` in the outer string. Any attempt to `chars.peek()` or `chars.next()` reads outer string content, not inner template content. Key-path resolution must use the already-extracted `template_key` string.

Also update the doc comment to reflect the new rules.

### Step 2: Deprecate `resolve_dollar_vars` — Unify Through `expand_string`

**File:** `crates/oxdock-core/src/exec/args.rs`

`resolve_dollar_vars` (line 444) is used by `evaluate_expr` for string literals inside expressions (`Expr::Literal(Value::String(s))` at line 60-62). This creates split semantics: bare `$var` interpolates in expression contexts but not in command contexts.

**Fix:** Delete `resolve_dollar_vars`. Route `Expr::Literal(Value::String(s))` through `expand_string` instead:

```rust
Expr::Literal(Value::String(s)) => {
    let ctx = cx.state.command_ctx()?;
    Ok(Value::String(expand_string(s, &ctx.envs(), cx.state)))
}
```

This ensures `{{ $var }}` is the sole interpolation trigger in every double-quoted string literal, regardless of whether it appears in `LET`, `IF`, `WRITE`, `ECHO`, or `RUN`.
