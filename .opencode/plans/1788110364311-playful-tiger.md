# Plan: Native IF/ELSE + Complete Expression System (Comparisons, Logical Ops, Parentheses)

## Context

The grammar, AST, and parser for `Expr::Compare` (`==`, `!=`) are already implemented. What remains:

1. **Evaluator**: `Expr::Compare` arm + `Expr::Logical` arm in `evaluate_expr` (args.rs)
2. **Macro emission**: `Expr::Compare` + `Expr::Logical` arms in `emit_expr` (lib.rs)
3. **Expression grammar upgrade**: 4-tier precedence climbing with parenthesized grouping
4. **Native IF/ELSE**: grammar, AST, parser, handler, tests

Guards (`[...]`) evaluate before script execution against `ExecIo` and OS metadata. They **cannot** inspect `$dsl_var` bindings. Runtime variable inspection requires a statement-level `IF`/`ELSE IF`/`ELSE` that executes in Phase 2.

## Architectural Constraint: Guards Must Remain Static

Guard clauses (`[...]`) are **static plan-pruning predicates** evaluated in Phase 1 against `ExecIo` ambient environment keys and OS platform properties. They must **never** be extended to evaluate dynamic `$dsl_var` bindings created mid-script by `LET`, `LOAD_JSON`, `LOAD_TOML`, or `FOR` iteration. Doing so introduces four fatal architectural defects:

1. **Destruction of Static Plan Pruning**: The runner discards disabled steps before execution begins. Dynamic guards make this impossible — the engine can no longer validate, optimize, or pre-allocate resources for the execution graph ahead of time. Guards become runtime `IF` statements wrapped in bracket syntax.

2. **O(N) Expression Redundancy for Fallback Branches**: Guards are instruction-level modifiers, not branching tree nodes. Without native `IF/ELSE`, fallback paths require inverse guards on sibling steps, forcing duplicate evaluation of the same runtime variable lookup and comparison for every iteration. An `IF/ELSE` AST node evaluates the conditional once.

3. **Scope Stack Inflation**: An `IF` statement evaluates the condition before entering the block — if false, no scope is allocated. A dynamic guard on a block enters the block node, allocates a child scope frame, *then* checks the guard — if false, it must immediately pop the frame. Across large `FOR` loops this creates unnecessary allocations.

4. **Stream Redirection Corruption**: Static guards prune steps before pipe handles are opened. Evaluating a dynamic guard after pipeline initialization forces teardown of open pipe handles mid-stream when the guard fails, causing stream stalls and unbuffered I/O leaks.

**Enforcement**: `StepKind::Guard` must never gain a runtime expression evaluation path. All dynamic branching goes through `StepKind::If`.

## Target Scripts

```text
// Compound conditions with precedence
IF ($node.kind == "template" && $node.active == "true") || $node.force == "1" {
    EXPAND $node.path
}

// Parenthesized sub-expressions override precedence
IF ($a == "1" || $b == "2") && $c == "3" {
    ECHO "combined"
}

// IF/ELSE IF/ELSE chain
IF $x == "1" { ECHO 1 } ELSE IF $x == "2" { ECHO 2 } ELSE { ECHO 3 }
```

## Phase 1: Expression Grammar — 4-Tier Precedence Climbing

**File:** `crates/oxdock-parser/src/dsl.pest`

Replace the current flat `expr` rule with a precedence-climbing grammar. Highest precedence at `expr_atom`, lowest at `expr_logical_or`:

```pest
// Non-silent atomic operators (generate AST nodes for parser iteration)
or_op  = @{ "||" }
and_op = @{ "&&" }
// eq_op and neq_op already exist at lines 53-54

// Parenthesized expression wrapper (allows recursive nesting)
parenthesized_expr = { "(" ~ expr ~ ")" }

// Precedence Level 0: Atoms (highest)
expr_atom = { parenthesized_expr | func_call | key_path | variable | list_literal | string_literal | bare_word }

// Precedence Level 1: Comparisons (==, !=)
expr_comparison = { expr_atom ~ ((eq_op | neq_op) ~ expr_atom)? }

// Precedence Level 2: Logical AND (&&)
expr_logical_and = { expr_comparison ~ (and_op ~ expr_comparison)* }

// Precedence Level 3: Logical OR (||) (lowest)
expr_logical_or = { expr_logical_and ~ (or_op ~ expr_logical_and)* }

// Entry point for all expressions
expr = { expr_logical_or }
```

**Precedence:** `()` > atoms > `==`/`!=` > `&&` > `||`. Left-associative within each tier. `&&` binds tighter than `||` (standard C/JS semantics).

**Note:** `bare_word` excludes `=`, `!`, `(`, `)`, `&`, `|` from its character class, so no conflict with operators. Parenthesized expressions are recursive (`parenthesized_expr` calls `expr` which routes through all tiers).

## Phase 3: Parser — Precedence-Climbing Dispatch

**File:** `crates/oxdock-parser/src/parser.rs`

Replace the current flat `parse_expr` / `parse_expr_comparison` / `parse_expr_atom` with a 4-tier cascade:

```rust
fn parse_expr(pair: Pair<Rule>) -> Result<Expr> {
    let inner = pair.into_inner().next().unwrap();
    match inner.as_rule() {
        Rule::expr_logical_or => parse_expr_logical_or(inner),
        _ => bail!("unexpected expr rule: {:?}", inner.as_rule()),
    }
}

fn parse_expr_logical_or(pair: Pair<Rule>) -> Result<Expr> {
    let mut inner = pair.into_inner();
    let mut left = parse_expr_logical_and(inner.next().unwrap())?;
    while let Some(op_pair) = inner.next() {
        let op = match op_pair.as_rule() {
            Rule::or_op => LogicalOp::Or,
            _ => bail!("unexpected operator in logical-or: {:?}", op_pair.as_rule()),
        };
        let right = parse_expr_logical_and(inner.next().unwrap())?;
        left = Expr::Logical { op, left: Box::new(left), right: Box::new(right) };
    }
    Ok(left)
}

fn parse_expr_logical_and(pair: Pair<Rule>) -> Result<Expr> {
    let mut inner = pair.into_inner();
    let mut left = parse_expr_comparison(inner.next().unwrap())?;
    while let Some(op_pair) = inner.next() {
        let op = match op_pair.as_rule() {
            Rule::and_op => LogicalOp::And,
            _ => bail!("unexpected operator in logical-and: {:?}", op_pair.as_rule()),
        };
        let right = parse_expr_comparison(inner.next().unwrap())?;
        left = Expr::Logical { op, left: Box::new(left), right: Box::new(right) };
    }
    Ok(left)
}

fn parse_expr_comparison(pair: Pair<Rule>) -> Result<Expr> {
    let mut inner = pair.into_inner();
    let left = parse_expr_atom(inner.next().unwrap())?;
    if let Some(op_pair) = inner.next() {
        let op = match op_pair.as_rule() {
            Rule::eq_op => CompareOp::Eq,
            Rule::neq_op => CompareOp::Ne,
            _ => bail!("unexpected comparison operator: {:?}", op_pair.as_rule()),
        };
        let right = parse_expr_atom(inner.next().unwrap())?;
        Ok(Expr::Compare { op, left: Box::new(left), right: Box::new(right) })
    } else {
        Ok(left)
    }
}

fn parse_expr_atom(pair: Pair<Rule>) -> Result<Expr> {
    let inner = pair.into_inner().next().unwrap();
    match inner.as_rule() {
        Rule::parenthesized_expr => parse_expr(inner.into_inner().next().unwrap()),
        Rule::func_call => parse_func_call(inner),
        Rule::key_path => parse_key_path(inner),
        Rule::variable => {
            let name = inner.as_str();
            let name = name.strip_prefix('$').unwrap_or(name).to_string();
            Ok(Expr::Var(name))
        }
        Rule::list_literal => parse_list_literal(inner),
        Rule::string_literal | Rule::quoted_string => {
            let s = parse_quoted_string(inner)?;
            Ok(Expr::Literal(Value::String(s)))
        }
        Rule::bare_word => {
            let s = inner.as_str().to_string();
            Ok(Expr::Literal(Value::String(s)))
        }
        _ => bail!("unexpected expression atom rule: {:?}", inner.as_rule()),
    }
}
```

**Key:** `parenthesized_expr` recursively calls `parse_expr` which re-enters the full precedence stack. This enables `(a || b) && c` to parse correctly.

### 3.1 Literal Parsing — `true`/`false` as `Value::Bool`

In `parse_expr_atom`, parse bare words `true` and `false` as `Value::Bool` instead of `Value::String`:

```rust
Rule::bare_word => {
    let s = inner.as_str().to_string();
    match s.as_str() {
        "true" => Ok(Expr::Literal(Value::Bool(true))),
        "false" => Ok(Expr::Literal(Value::Bool(false))),
        _ => Ok(Expr::Literal(Value::String(s))),
    }
}
```

This ensures `IF true` and `LET $x = false` produce native booleans, not strings. Combined with `LOAD_TOML`/`LOAD_JSON` mapping native bools to `Value::Bool` via `json_to_value`, the DSL has a clean boolean path from data loading to conditional evaluation.

### 4.3 Add `Expr::Logical` arm with short-circuit evaluation

```rust
Expr::Logical { op, left, right } => {
    let left_val = evaluate_expr(left, cx)?;
    let left_truthy = is_truthy(&left_val)?;
    match op {
        LogicalOp::Or => {
            if left_truthy {
                Ok(Value::Bool(true))
            } else {
                Ok(Value::Bool(is_truthy(&evaluate_expr(right, cx)?)?))
            }
        }
        LogicalOp::And => {
            if !left_truthy {
                Ok(Value::Bool(false))
            } else {
                Ok(Value::Bool(is_truthy(&evaluate_expr(right, cx)?)?))
            }
        }
    }
}
```

### 4.4 Add `is_truthy` helper (strict boolean requirement)

```rust
pub(crate) fn is_truthy(val: &Value) -> Result<bool> {
    match val {
        Value::Bool(b) => Ok(*b),
        other => bail!("Type Error: condition must be a Bool, found {:?}", other),
    }
}
```

**Strict boolean model (Option A):** IF statements and logical operators require `Value::Bool`. Non-boolean values (strings, lists, maps) produce a `TypeError` at runtime. This prevents the `"false"` string bug where `Value::String("false")` would incorrectly evaluate as truthy under structural truthiness. Authors must use explicit comparisons (`IF $x == "true"` or `IF $x == false`) instead of relying on weak dynamic coercions.

## Phase 5: IF/ELSE Grammar

**File:** `crates/oxdock-parser/src/dsl.pest`

**MUST NOT**: Do not add runtime expression evaluation to `guard_line`, `guard_predicate`, `bool_guard`, or any guard-related rule. Guards remain static plan-pruning predicates. All dynamic branching goes through `if_statement`.

```pest
if_keyword = @{ "IF" ~ !(ASCII_ALPHANUMERIC | "_") }
else_keyword = @{ "ELSE" ~ !(ASCII_ALPHANUMERIC | "_") }
else_if_clause = { else_keyword ~ if_keyword ~ expr ~ block }
else_clause = { else_keyword ~ block }
if_statement = { if_keyword ~ expr ~ block ~ else_if_clause* ~ else_clause? }
```

**Note:** `!(ASCII_ALPHANUMERIC | "_")` ensures `IF_FLAG` or `ELSE_MODE` are not sliced into keyword + dangling suffix. Fix `for_keyword`, `in_keyword`, `let_keyword` to use the same `!(ASCII_ALPHANUMERIC | "_")` pattern for consistency.

Update `element` and `block_element`:

```pest
element = _{ blank | hash_comment | semicolon | guard_line | block_start | block_end | if_statement | for_statement | let_statement | command }
block_element = _{ blank | hash_comment | semicolon | guard_block | guard_line | if_statement | for_statement | let_statement | command }
```

## Phase 8: IF/ELSE Handler

**File:** `crates/oxdock-core/src/exec/handlers.rs`

**Architectural note**: This handler executes in Phase 2 (sequential step execution) against `ExecState`. It evaluates the condition expression via `evaluate_expr` which reads `$dsl_var` bindings from `var_scopes`. This is the *only* correct path for dynamic runtime branching. Guard predicates in `guard_allows` / `guard_expr_allows` (ast.rs) must never gain access to `ExecState` or `var_scopes`.

```rust
pub(super) fn if_then<P: ProcessManager>(
    cx: &mut StepCtx<'_, P>,
    cond: &Expr,
    then_body: &[Step],
    else_ifs: &[(Box<Expr>, Vec<Step>)],
    else_body: &Option<Vec<Step>>,
) -> Result<()> {
    let val = super::args::evaluate_expr(cond, cx)?;
    if super::args::is_truthy(&val)? {
        return super::steps::execute_steps(
            cx.state, cx.process, then_body, cx.stdin.clone(),
            false, cx.out.clone(), cx.err.clone(), false,
        );
    }
    for (else_cond, else_block) in else_ifs {
        let val = super::args::evaluate_expr(else_cond.as_ref(), cx)?;
        if super::args::is_truthy(&val)? {
            return super::steps::execute_steps(
                cx.state, cx.process, else_block, cx.stdin.clone(),
                false, cx.out.clone(), cx.err.clone(), false,
            );
        }
    }
    if let Some(body) = else_body {
        super::steps::execute_steps(
            cx.state, cx.process, body, cx.stdin.clone(),
            false, cx.out.clone(), cx.err.clone(), false,
        )?;
    }
    Ok(())
}
```

`is_truthy` is `pub(crate)` in `args.rs` and enforces strict `Value::Bool` typing.

**File:** `oxdock-macros/src/lib.rs` — Add `Expr::Logical` and `StepKind::If` emission arms with fully-qualified paths and `interp` passthrough. Key type constraints:
- `StepKind::If.cond` is `Box<Expr>` → emit `Box::new(#cond_tokens)`
- `StepKind::If.else_ifs` is `Vec<(Box<Expr>, Vec<Step>)>` → emit `(Box::new(#ec), vec![...])`

```rust
// Expr::Logical emission
Expr::Logical { op, left, right } => {
    let op_token = match op {
        oxdock_parser::ast::LogicalOp::And => quote! { oxdock_parser::ast::LogicalOp::And },
        oxdock_parser::ast::LogicalOp::Or => quote! { oxdock_parser::ast::LogicalOp::Or },
    };
    let left_tokens = emit_expr(left, interp);
    let right_tokens = emit_expr(right, interp);
    quote! {
        oxdock_parser::ast::Expr::Logical {
            op: #op_token,
            left: Box::new(#left_tokens),
            right: Box::new(#right_tokens),
        }
    }
}

// StepKind::If emission
StepKind::If { cond, then_body, else_ifs, else_body } => {
    let cond_tokens = emit_expr(cond, interp);
    let then_tokens: Vec<_> = then_body.iter().map(|s| emit_step(s, interp)).collect();
    let else_if_tokens: Vec<_> = else_ifs.iter().map(|(c, b)| {
        let ec = emit_expr(c, interp);
        let eb: Vec<_> = b.iter().map(|s| emit_step(s, interp)).collect();
        quote! { (Box::new(#ec), vec![#(#eb),*]) }
    }).collect();
    let else_tokens = match else_body {
        Some(body) => {
            let eb: Vec<_> = body.iter().map(|s| emit_step(s, interp)).collect();
            quote! { Some(vec![#(#eb),*]) }
        }
        None => quote! { None },
    };
    quote! {
        oxdock_parser::ast::StepKind::If {
            cond: Box::new(#cond_tokens),
            then_body: vec![#(#then_tokens),*],
            else_ifs: vec![#(#else_if_tokens),*],
            else_body: #else_tokens,
        }
    }
}
```
