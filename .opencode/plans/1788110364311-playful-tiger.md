# Plan: Docker-Style Default Expansion + Delete RAW_WRITE

## Context

All strings expand by default. `\$` → literal `$`, `\{{` → literal `{{`. Delete `RAW_WRITE`.

**Escape rules:**
- `\\` → literal `\`
- `\$` → literal `$`, skips variable lookup
- `\{{` → literal `{{`, skips template expansion
- All other `$` and `{{` expand normally

**Single source of truth:** ALL backslash processing happens in one place — `expand_string` at runtime. The parser passes string contents verbatim (no escape stripping).

```rust
pub(crate) fn expand_string(input: &str, state: &ExecState) -> String {
    let mut output = String::new();
    let mut chars = input.chars().peekable();
    while let Some(c) = chars.next() {
        match c {
            '\\' => match chars.peek() {
                Some(&'\\') => { output.push('\\'); chars.next(); }
                Some(&'$') => { output.push('$'); chars.next(); }
                Some(&'n') => { output.push('\n'); chars.next(); }

                }
                _ => output.push('\\'),
            },
            '$' => { /* collect variable name, look up, emit value */ }
            '{' if chars.peek() == Some(&'{') => {
                chars.next();
                /* collect until }}), expand env:KEY */
            }
            _ => output.push(c),
        }
    }
    output
}
```

## Appendix: `{{ $a }}` as Unified Interpolation Syntax

### Motivation

The current model uses bare `$a` for variable interpolation inside strings (e.g., `"$a.txt"`). This creates ambiguity with dot-notation field access and forces `\$` escaping for literal dollar signs. Switching to `{{ $a }}` as the *only* interpolation trigger inside double-quoted strings solves these problems cleanly.

### Key Benefits

#### 1. Eliminates `\$` Escaping Noise

If `$` only evaluates inside `{{ ... }}`, bare `$` signs inside normal strings remain 100% literal text.

- `"Price is $5.00"` requires zero backslash escaping.
- `"jQuery $ is ready"` requires zero backslash escaping.
- Only `"{{ $price }}"` triggers variable lookup.

#### 2. Eliminates `$a.txt` Ambiguity

- **Inside expressions (`LET`, `IF`):** `$a.txt` is unambiguously an object field access on `$a`.
- **Inside strings (`WRITE`):** `"{{ $a }}.txt"` is unambiguously variable `$a` followed by literal string `.txt`.

#### 3. Maintains Variable Identifier Parity

Because script variables start with `$` everywhere else in the language (`LET $a = "notes"`, `FOR $item IN $list`), using `{{ $a }}` inside strings maintains the `$` symbol everywhere. You don't have to remember to drop the `$` when moving a variable inside a string.

### Syntax Comparison

| Scenario | Original Mixed Model | Proposed `{{ $a }}` Model |
| --- | --- | --- |
| **Local Variable String** | `"$a.txt"` | `"{{ $a }}.txt"` |
| **Env Variable String** | `"{{ env:USER }}"` | `"{{ env:USER }}"` (or `"{{ $env.USER }}"`) |
| **Literal Dollar Sign** | `"\$5.00"` | `"$5.00"` |
| **Literal Template Braces** | `"\{{ env:USER }}"` | `"\{{ env:USER }}"` |

### Implementation Notes

- **Grammar change:** Inside `message` / `run_args` / `argument` string literals, `{{ ... }}` is the *only* trigger for variable expansion. Bare `$` is literal.
- **Expression contexts** (`LET`, `IF`, `FOR ... IN`): `$a.b.c` continues to work as field access — no change needed.
- **`expand_string` update:** Remove the `$` → variable interpolation branch. `{{ }}` handles both `$var` and `env:KEY` lookups.
- **Backward compatibility:** Existing scripts using `"$var"` in strings will break — this is a deliberate breaking change. Migration: `"$var"` → `"{{ $var }}"`.

### Step 1: Modify `expand_string` — Remove Bare `$` Interpolation, Enhance `{{ }}`

**File:** `crates/oxdock-core/src/exec/args.rs`

**1a. Remove bare `$` interpolation:**

In `expand_string` (line 280), remove the `'$' => { ... }` match arm (lines 330-401). Bare `$` now falls through to the `_ => output.push(c)` default, producing literal `$`.

Keep the `'\\'` arm but remove the `\$` sub-case (no longer needed — bare `$` is already literal). Keep `\{{`, `\\`, `\n`, `\t`, `\r`, `\"`.

**1b. Enhance `{{ }}` handler for `$var` scope lookup:**

The current `{{ }}` handler (lines 402-431) only looks up keys in `env`. Extend it to support `{{ $var }}` and `{{ $var.path.0 }}` by parsing the extracted `template_key` string directly — NOT by reading from `chars` (which has already advanced past `}}`).

```rust
'{' if chars.peek() == Some(&'{') => {
    chars.next(); // consume second {
    let mut template_key = String::new();
    let mut found_close = false;
    while let Some(ch) = chars.next() {
        if ch == '}' && chars.peek() == Some(&'}') {
            chars.next(); // consume second }
            found_close = true;
            break;
        }
        template_key.push(ch);
    }
    if found_close {
        let key = template_key.trim();
        if let Some(var_expr) = key.strip_prefix('$') {
            // {{ $var }} or {{ $var.path.0 }} — look up in scope chain.
            // Parse key-path from the extracted string, NOT from chars.
            // Trim whitespace from segments to tolerate spaces around dots.
            let mut parts = var_expr.split('.');
            if let Some(base_var) = parts.next() {
                let base_trim = base_var.trim();
                let mut current = state.get_var(base_trim)
                    .or_else(|| env.get(base_trim).map(|v| Value::String(v.clone())));
                for part in parts {
                    let part_trim = part.trim();
                    current = match current {
                        Some(Value::Map(map)) => map.get(part_trim).cloned(),
                        Some(Value::List(list)) => {
                            part_trim.parse::<usize>().ok()
                                .and_then(|idx| list.get(idx).cloned())
                        }
                        _ => None,
                    };
                    if current.is_none() { break; }
                }
                if let Some(v) = current {
                    output.push_str(&format_value_for_string(&v));
                }
                // Missing → emit empty (matches StreamingExpand)
            }
        } else {
            // {{ env:KEY }} or {{ bare_key }} — look up in env
            let env_key = key
                .strip_prefix("env:")
                .or_else(|| key.strip_prefix("script_env:"))
                .unwrap_or(key);
            if let Some(val) = env.get(env_key) {
                output.push_str(val);
            }
            // Missing → emit empty
        }
    } else {
        output.push_str("{{");
        output.push_str(&template_key);
    }
}
```

**Why not read from `chars`:** The `while` loop that collects `template_key` advances `chars` past the entire `}}` delimiter. After the loop, `chars` points to the character *after* `}}` in the outer string. Any attempt to `chars.peek()` or `chars.next()` reads outer string content, not inner template content. Key-path resolution must use the already-extracted `template_key` string.

Also update the doc comment to reflect the new rules.

## Phase 10: Restore Docker-Style Unquoted Arguments

### Goal

Re-introduce `unquoted_arg` to the grammar so `WRITE dist/hello.txt`, `WORKDIR /app`, and `RUN echo hello` work without forcing double quotes around every path. Aligns OxDock with Dockerfile conventions while retaining `{{ $var }}` as the sole interpolation trigger.

### Step 1: Grammar — `dsl.pest`

**File:** `crates/oxdock-parser/src/dsl.pest`

Add `unquoted_arg` and restore it to `argument`, `env_value_part`, `message`, and `run_args`:

```pest
// Unquoted arguments — Docker-style bare words
// Leading !$ rejects tokens starting with $ (forces $var to expr).
// Inner loop excludes { to prevent consuming {{ }} as a single token.
unquoted_arg = @{ !"$" ~ (!WHITESPACE ~ !linebreak ~ !";" ~ !"}" ~ !"{" ~ !"//" ~ !"/*" ~ ANY)+ }

// argument repeats to support contiguous fragments: dist/{{ $file }}.txt
// PEG ordered choice per fragment: string_literal → templated_arg → unquoted_arg → expr
// Single expr fragment → Arg::Expr; mixed/string fragments → Arg::String via concatenation.
argument = { (string_literal | templated_arg | unquoted_arg | expr)+ }

// message and run_args: each fragment can be unquoted
message = { (string_literal | templated_arg | unquoted_arg | expr)+ }
run_args = { (string_literal | templated_arg | unquoted_arg | expr)+ }

// env_value: unquoted or quoted
env_value_part = { (string_literal | templated_arg | unquoted_env_value | expr)+ }
unquoted_env_value = @{ !"$" ~ (!WHITESPACE ~ !linebreak ~ !";" ~ !"}" ~ !"{" ~ !"//" ~ !"/*" ~ ANY)+ }
```

**Why `unquoted_arg` before `expr`:** PEG tries alternatives in order. A bare word like `dist/hello.txt` matches `bare_word` inside `expr`, which wraps it in `Expr::Literal(Value::String(...))` → `Arg::Expr`. By placing `unquoted_arg` before `expr`, bare words parse as `Arg::String` and route through `expand_string` instead of expression evaluation. The leading `!"$"` assertion rejects tokens starting with `$`, forcing `$var` and `$a.b.c` to fall through to `expr` (via `variable`/`key_path`). Non-initial `$` in unquoted paths (e.g., `dist/$file.txt`) is accepted as literal text. The inner `!"{"` exclusion prevents `{{ }}` template syntax from being consumed as a single unquoted token.

**Why `argument` uses `(...)+`:** A single `argument` rule must handle both simple paths (`WORKDIR /app`) and interpolated paths (`WORKDIR dist/{{ $file }}/app`). The `+` quantifier allows `unquoted_arg("dist/")` + `templated_arg("{{ $file }}")` + `unquoted_arg("/app")` to be parsed as one contiguous argument. `parse_argument` concatenates these into `Arg::String("dist/{{ $file }}/app")`, which `expand_string` processes at runtime. Commands reference `argument` exactly once (e.g., `workdir_command = ${ "WORKDIR" ~ sep ~ argument }`), so the repetition is contained within a single argument slot.

### Step 2: Parser — `parser.rs`

**File:** `crates/oxdock-parser/src/parser.rs`

**2a.** Refactor `parse_argument` to handle multi-fragment sequences. If the `argument` node contains a single `expr` child, return `Arg::Expr`. Otherwise, concatenate all fragments via `parse_concatenated_fragments` and return `Arg::String`:

```rust
fn parse_argument(pair: Pair<Rule>) -> Result<Arg> {
    let inner: Vec<_> = pair.into_inner().collect();
    // Single expression — preserve as Arg::Expr for runtime evaluation
    if inner.len() == 1 && inner[0].as_rule() == Rule::expr {
        return Ok(Arg::Expr(parse_expr(inner.into_iter().next().unwrap())?));
    }
    // Mixed fragments (string, template, unquoted) — concatenate into Arg::String
    // Rebuild a synthetic pair-like structure for parse_concatenated_fragments
    let combined = parse_concatenated_fragments_from_parts(&inner)?;
    Ok(Arg::String(combined))
}
```

**2b.** Extract `parse_concatenated_fragments` into a helper that accepts a slice of `Pair`s, so both `parse_argument` and `parse_message`/`parse_run_args` can use it:

```rust
fn parse_concatenated_fragments_from_parts(parts: &[Pair<Rule>]) -> Result<String> {
    // Single string literal: unquote
    if parts.len() == 1 && parts[0].as_rule() == Rule::string_literal {
        let s = parts[0].as_str();
        return Ok(s[1..s.len() - 1].to_string());
    }
    let mut body = String::new();
    let mut last_end = None;
    for part in parts {
        let span = part.as_span();
        if let Some(end) = last_end && span.start() > end {
            body.push(' ');
        }
        match part.as_rule() {
            Rule::string_literal => {
                let s = part.as_str();
                let unquoted = &s[1..s.len() - 1];
                // ... (same logic as current parse_concatenated_fragments)
                body.push_str(unquoted);
            }
            Rule::templated_arg | Rule::unquoted_arg | Rule::unquoted_env_value => {
                body.push_str(part.as_str());
            }
            Rule::expr => body.push_str(part.as_str()),
            _ => {}
        }
        last_end = Some(span.end());
    }
    Ok(body)
}
```
