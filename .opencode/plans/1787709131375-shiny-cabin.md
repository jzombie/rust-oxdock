### Extraction
- Locate README.md via `PathResolver::from_manifest_env()?.root()?.join("README.md")`
- Line-scan fences: opening ```` ``` ```` runs of ≥3 backticks; block is DSL iff info string is exactly `oxdock`. Ignore all other languages (`bash`, `text`, `rust`, `toml`). Track fence depth; closing fence must have backtick-run ≥ opener's
- Per block produce `{ line_no, directives: Vec<Directive>, body: String }`; error messages include README line number + first body line
- Directive lines = start (col 0) with `#>` (stripped before parsing); continuation lines start with `#|` and append `\n` + content to previous directive's value

### Directive grammar (mirrors case.toml `[expect]` vocabulary)
```
#> env: KEY=value          inject via ExecIo::insert_inherit_env
#> stdin: text             feed via SharedInput (Arc<Mutex<Cursor<Vec<u8>>>>)
#> stdout: substring       assert captured stdout contains (repeatable, #| for multiline)
#> files: path = content   exact match under workspace root (repeatable, #| continuations)
#> missing: path           path must not exist
#> dirs: path              directory must exist
#> pipes: name=substring   register capturing pipe name (insert_output_pipe) + assert content contains
#> error: substring        script must fail; anyhow message contains substring
#> [windows] <directive>   optional platform prefix (unix|windows|macos|linux|mac) — directive applies only on matching os
```
- Unknown directive names / malformed forms → hard failure (typo-proofing)
- No directives ⇒ default assertion is just parse+execute success

### Execution flow (`docs_execute_examples`)
Per block, isolated `GuardedPath::tempdir()` as both fs_root and build_context (mirrors ast_commands fixture):
1. Build `ExecIo`: inject env, stdin, stdout/stderr capture (`Arc<Mutex<Vec<u8>>>`), pipes
2. `parse_script(&body)` must succeed
3. `run_steps_with_context_result_with_io(&root, &root, &steps, io)`
4. On `error:` expectation assert failure + substring; else unwrap Ok
5. Assert files/dirs/missing/pipes/stdout per directives; strip `\r` from captured output before substring matching (Windows CRLF); read files via `PathResolver::read_to_string`

### Parse + coverage gate (`docs_parse_and_coverage`)
- Every `oxdock` block body must `parse_script()` OK (directives stripped)
- Iterate `oxdock_parser::...::COMMANDS` (verify export path `ast::COMMANDS` vs re-export at impl time) — for each `command.as_str()` require ≥1 block whose **body** contains that keyword as a token
- Cheap tripwires: README must contain `or(`, `{{ `, `[env:` somewhere in fenced bodies (structural-feature coverage)

### Constraints honored
- Only `oxdock-fs` abstractions (no raw `std::fs`); no `cfg!(miri)` — only the `#[cfg_attr(miri, ignore = "...")]` skip with reason
- `indoc` not needed here (snippets come from README), but follow repo style otherwise
- No comments beyond what's idiomatic; clippy `-D warnings` clean
