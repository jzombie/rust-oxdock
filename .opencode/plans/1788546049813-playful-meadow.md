# Plan: True ASYNC — All Commands in Background Threads with Subshell Isolation

## Goal

Replace the fake ASYNC (shell-concatenated `RUN` commands only) with true ASYNC that executes ALL command types in background threads with subshell isolation. `ASYNC { WRITE ...; COPY ...; RUN ... }` works. Mutations (ENV, WORKDIR) stay within the block.

## Design: Subshell Isolation via State Forking

Each `ASYNC` block spawns a **background thread** with a **forked `ExecState`**. The child gets independent copies of filesystem, envs, cwd, var_scopes. Mutations inside the block don't leak to the parent. This is equivalent to POSIX `( ... )` subshell semantics.

## Send-ability Barriers & Solutions

| Barrier | Solution |
|---------|----------|
| `WorkspaceFs` has no `Send` bound | Add `Send + Sync` supertrait |
| `open_read`/`open_write` return `Box<dyn Read>`/`Box<dyn Write>` | Change to `Box<dyn Read + Send>` / `Box<dyn Write + Send>` |
| `MockFs` uses `Rc<RefCell<...>>` | Change to `Arc<Mutex<...>>` |
| `MockProcessManager` uses `Rc<RefCell<...>>` | Change to `Arc<Mutex<...>>` with shared inner |
| `MockHandle` uses `Rc<RefCell<...>>` | Change to `Arc<Mutex<...>>` |
| `ProcessManager` has no `Send` bound | Add `Clone + Send + 'static` |
| `BackgroundHandle` has no `Send` bound | Add `Send` |
| `bg_children: Vec<P::Handle>` can't hold thread handles | Change to `Vec<Box<dyn BackgroundHandle>>` |
| `Box<dyn WorkspaceFs>` can't be cloned across threads | Add `clone_box()` method |

## Phase 4: Thread-Based Execution

### `crates/sys/oxdock-process/src/contract.rs` — Split ProcessManager for interruptible waits
- Add `Clone + Send + Sync + 'static` supertraits to `ProcessManager`:
  ```rust
  pub trait ProcessManager: Clone + Send + Sync + 'static {
      type Handle: BackgroundHandle + Clone + Send + 'static;
      // ...
  }
  ```
- **DO NOT** add `Clone` to `BackgroundHandle` — it breaks object safety (`Box<dyn BackgroundHandle>`). `Clone` is bound only on `ProcessManager::Handle`:
  ```rust
  pub trait BackgroundHandle: Send {
      fn try_wait(&mut self) -> Result<Option<ExitStatus>>;
      fn kill(&mut self) -> Result<()>;
      fn wait(&mut self) -> Result<ExitStatus>;
  }
  ```
- Add `spawn_command` method to `ProcessManager`:
  ```rust
  fn spawn_command(
      &self,
      ctx: &CommandContext,
      script: &str,
      options: CommandOptions,
  ) -> Result<CommandResult<Self::Handle>>;
  ```
- `handlers::run` (foreground): call `spawn_command`, clone handle into `cx.state.active_process` as `Box::new(handle.clone())` (drop mutex guard BEFORE calling `handle.wait()`), then call `handle.wait()`. Clear `active_process` after wait completes. This avoids holding the mutex during the blocking wait, allowing `ThreadJoinHandle::kill()` to lock `active_process` and interrupt the running process.
- OS process handle implementations (`ChildHandle`) must use shared inner state (`Arc<Mutex<Option<Child>>>`) so that calling `kill()` on a cloned handle terminates the underlying OS process and unblocks `wait()` on the original handle.

### `crates/oxdock-core/src/exec/steps.rs`
- Add `ThreadJoinHandle` type implementing `BackgroundHandle`:
  ```rust
  pub(super) struct ThreadJoinHandle {
      join: Option<std::thread::JoinHandle<Result<()>>>,
      cancel_token: Arc<AtomicBool>,
      active_process: Arc<Mutex<Option<Box<dyn BackgroundHandle>>>>,
  }
  ```
  - `try_wait()`: checks `is_finished()`, reaps, returns exit code
  - `kill()`: sets `cancel_token` (SeqCst), kills `active_process` (poison-safe: `unwrap_or_else(|e| e.into_inner())`), **joins** the thread (`handle.join()`) to ensure it completes before returning — this prevents detached threads from racing against workspace teardown. Returns Ok.
  - `wait()`: blocks on join
  - Thread panic → exit code 1
  - `impl Drop` calls `self.kill()` — ensures cleanup when handle is dropped during unwind

### Fail-fast survivor teardown in poll-all loop
- **Poll BOTH `bg_children` AND `named_tasks`.** Kill survivors immediately on first failure:
  ```rust
  let has_bg = !state.bg_children.is_empty();
  let has_named = !state.named_tasks.lock().unwrap_or_else(|e| e.into_inner()).is_empty();
  if wait_at_end && (has_bg || has_named) {
      loop {
          let mut failed_status: Option<anyhow::Error> = None;

          // 1. Poll anonymous background handles
          let mut i = 0;
          while i < state.bg_children.len() {
              match state.bg_children[i].try_wait() {
                  Ok(Some(status)) => {
                      if !status.success() && failed_status.is_none() {
                          failed_status = Some(anyhow!("ASYNC process exited with status {status}"));
                          break;
                      }
                      state.bg_children.swap_remove(i);
                  }
                  Ok(None) => { i += 1; }
                  Err(e) => {
                      if failed_status.is_none() { failed_status = Some(e); }
                      break;
                  }
              }
          }

          // 2. Poll un-awaited named tasks
          if failed_status.is_none() {
              let mut named = state.named_tasks.lock().unwrap_or_else(|e| e.into_inner());
              named.retain(|id, task| {
                  match task.try_wait() {
                      Ok(Some(status)) => {
                          if !status.success() && failed_status.is_none() {
                              failed_status = Some(anyhow!("named ASYNC task {id} exited with status {status}"));
                          }
                          false // remove completed task
                      }
                      Ok(None) => true, // retain running task
                      Err(e) => {
                          if failed_status.is_none() { failed_status = Some(e); }
                          false
                      }
                  }
              });
          }

          // 3. Fail-fast teardown
          if let Some(err) = failed_status {
              for survivor in state.bg_children.iter_mut() {
                  let _ = survivor.kill();
              }
              let mut named = state.named_tasks.lock().unwrap_or_else(|e| e.into_inner());
              for survivor in named.values_mut() {
                  let _ = survivor.kill();
              }
              state.bg_children.clear();
              named.clear();
              return Err(err);
          }

          let bg_empty = state.bg_children.is_empty();
          let named_empty = state.named_tasks.lock().unwrap_or_else(|e| e.into_inner()).is_empty();
          if bg_empty && named_empty { break; }
          std::thread::sleep(std::time::Duration::from_millis(10));
      }
  }
  ```

### Env isolation via copy-on-write
- In `handlers::env` and `handlers::inherit_env`: use `Arc::make_mut(&mut state.envs)` before mutating. This ensures forked task subscopes get their own env copy on first mutation, preserving isolation.

### Uninterruptible native file I/O (accepted limitation)
- `cancel_token` is only checked between steps. Long-running native operations (`COPY`, `WRITE`, `HASH_SHA256`) cannot be interrupted mid-operation. The thread continues until the current step completes, then checks `cancel_token`.
- This is a fundamental limitation of cooperative cancellation with synchronous I/O. The child operates on forked state, so it cannot corrupt the parent's state. The worst case is a delayed cleanup of the child thread.
- Future mitigation: wrap file I/O in chunked readers/writers that check `cancel_token` between 64KiB chunks.

### Output interleaving
- `cx.out`/`cx.err` are `StreamHandle` which wraps `SharedOutput = Arc<Mutex<dyn Write + Send>>`
- Multiple concurrent ASYNC threads sharing the same output stream may interleave bytes
- **Acceptable for now**: individual `write()` calls are mutex-serialized, but consecutive writes from different threads may interleave at byte boundaries. Document this limitation.

## Phase 5: AWAIT — Named Task Handles

Without AWAIT, ASYNC is fire-and-forget. A foreground step depending on an artifact produced by a background task creates file race conditions. AWAIT provides an explicit join primitive.

### Syntax

```oxdock
LET $build = ASYNC RUN "cargo build --release"
ECHO "compilation started..."
AWAIT $build
RUN "./target/release/app"

LET $test = ASYNC {
    RUN "cargo test --lib"
    WRITE "results.txt" "done"
}
AWAIT $test
RUN "cat results.txt"
```

## Risk: ThreadCancellation

`ThreadJoinHandle::kill()` sets `cancel_token` (SeqCst), kills the `active_process` handle to interrupt any blocking OS `wait()` syscall (via the new `spawn_command` API), and **joins** the worker thread. Joining ensures the thread completes before `kill()` returns, preventing detached threads from racing against workspace cleanup. `impl Drop` calls `kill()`. Mutex poisoning in `Drop` is handled via `unwrap_or_else(|e| e.into_inner())`.

## Risk: CrossHandleInterruption

`ChildHandle` must use shared inner state (`Arc<Mutex<Option<Child>>>`) so that `kill()` on a cloned handle terminates the underlying OS process and unblocks `wait()` on the original handle. If handles own the child process exclusively, cloning and killing a handle will not interrupt the blocking wait.

## Risk: OutputInterleaving

Multiple concurrent ASYNC threads sharing the same `cx.out`/`cx.err` may interleave bytes at arbitrary boundaries. Individual `write()` calls are mutex-serialized, but consecutive writes from different threads may interleave. Cosmetic issue, not correctness. Acceptable for now.

## Risk: UninterruptibleFileIO

Native filesystem operations (`COPY`, `WRITE`, `HASH_SHA256`) cannot be interrupted mid-operation by `cancel_token`. The thread continues until the current step completes, then checks `cancel_token`. This is a fundamental limitation of cooperative cancellation with synchronous I/O. The child operates on forked state, so it cannot corrupt the parent's state. Future mitigation: chunked I/O with cancellation checks.

## Risk: UnboundedThreads

Using `std::thread::spawn` directly allows unbounded thread creation. For MVP this is acceptable — oxdock scripts are typically short-lived build scripts, not long-running servers. A bounded thread pool can be added later if needed.
