## Context

Host-side honesty is done: every `#[oxdock_func]` parameter renders an
enforced tag (`ANY`, `MAP`, `LIST`, `LIST<MAP>`, `#[values]` sets), all
derived from one macro source. This plan covers the script side:
`FUNC` bodies are currently return-unchecked (fallthrough yields `""`,
any branch mix is accepted). A run-start static pass makes script
functions as airtight as host signatures. All four review directives
are adopted verbatim (MissingReturn, unidirectional ANY, flow-sensitive
env, loop/guard exhaustiveness).

## Structural facts (verified read-only)

- `FuncDef { name, params: Vec<(String,String)>, body: Vec<Step> }`
  (`crates/oxdock-parser/src/commands.rs:821`). Param type words are
  resolved at define time via `resolve_tag` (`oxdock-core/.../handlers.rs:1841-1856`).
  **No declared return type exists** — returns are inferred.
- `Return { expr: Box<Expr> }` (`commands.rs:823`); bare `RETURN`
  yields `Literal("")`. Fallthrough yields `""`
  (`call_func_value`, `handlers.rs:1867-1946`: `Flow::Done => Ok("")`).
- `Step { guard: Option<GuardExpr>, kind, scope_enter, scope_exit }`
  (`oxdock-parser/src/ast.rs:586-591`). Guards classify statically:
  `StaticBool(true)` (incl. absent guard) = unconditional;
  `StaticBool(false)` = statically unreachable (excluded from Phase A
  and B entirely — classification, unification, completeness, and
  checking); every other guard (env, platform, compound) =
  conditional. No conservatism gap: dead code cannot trigger
  `MissingReturn`, and live code cannot hide behind a dead `RETURN`.
- `If { cond, then_body, else_ifs, else_body }` (`commands.rs:809`);
  branches run scoped (`execute_scoped_steps`). `For { ..., var,
  var_type, in_expr, body }` (`commands.rs:808`) — zero-trip possible.
  `While { cond, body }` (`commands.rs:824`).
- `Assign { var, decl_type, expr }` = `LET` (`commands.rs:810`);
  `Set { var, expr }` = mutate (`commands.rs:811`).
  `declare_var`/`mutate_var` (`oxdock-core/src/exec/state.rs:359-400`)
  **coerce at runtime** — so `Set` never changes a var's type; only
  `Assign` (same-scope redeclaration is already a runtime error).
- `Expr` variants (`oxdock-parser/src/ast.rs:527-583`): `Literal`,
  `Var`, `Env`, `KeyPath`, `List`, `Map`, `Block` (fallthrough `""`),
  `Call`, `Inspect`, `Compare`, `Arithmetic`, `CompiledMath`, `FreshPipe`,
  `Not`, `Logical`, `UnsignedIntBoundary`.
- Hook point: `finish_run` (`oxdock-core/src/exec/mod.rs:369-377`)
  calls `state.validate_function_type_tags()` before `execute_steps`.
  The new pass runs beside it, same fail-before-first-step contract.
- `TypeTag::builtin()` (`oxdock-parser/src/tag.rs:104-120`) has **no
  `ANY` arm** — must add `"ANY" => Some(TypeTag::Any)` so `LET $x: ANY`
  and `: ANY` params resolve. `resolve_tag` (`typing.rs:87-104`) then
  accepts it with no further change.

  (`oxdock-logic-tests/fixtures/commands/ast_commands/cases/`).

## Design: `validate_script_types` (new file `oxdock-core/src/exec/static_check.rs`)

Run-start pass over top-level steps + every `FuncDef` body (nested
included). Two phases:

**Phase A — collect + infer.** Walk the whole tree, register every
`FuncDef` (params resolved via `state.resolve_tag`, as today). Infer
each body return type from terminal unification (rules below). Calls
to a `FUNC` currently being inferred (recursion/forward ref) yield
`ANY` — sound widening, documented.

**Phase B — check.** Flow-sensitive env (`HashMap<String, TypeTag>`)
propagated sequentially; fork at `If` arms, unify at merge
(`T`+`T`=`T`, `T`+`ANY`=`ANY`, mismatch = error); `Set` keeps type;
`Assign` declares; `For` binds loop var(s) in body only. Check every
body + top-level steps.

### Expression inference (`infer_expr`)

- `Literal` → word tag via `TypeTag::builtin` on the word name;
  unmapped words → `ANY`.
- `Var` / `KeyPath` base / `Inspect(name)` → env lookup; absent =
  static undeclared-variable error. `KeyPath`: `Record` base with
  known field → field type, else `ANY`.
- `Env` → `STRING`. `FreshPipe` → `PIPE`. `Compare`/`Not`/`Logical`
  → `BOOL` (verify against evaluators during implementation).
  `Arithmetic`/`CompiledMath` → `ANY` (coercion semantics live at
  runtime; widening is sound).
- `List`/`Map` literals → `LIST`/`MAP` (element/field shapes stay
  runtime-checked).
- `Arithmetic { op, left, right }` → exact operative rules, verified
  against `apply_arith` (`oxdock-core/src/exec/args.rs:438-469`):
  `INT op INT` → `INT` (checked, integer division); any `FLOAT`
  among numeric operands → `FLOAT`; unary negation preserves
  (`INT`→`INT`, `FLOAT`→`FLOAT`); any `ANY` operand → `ANY` (only
  fallback). Non-numeric operand pairs (both concrete, neither
  numeric, neither `ANY`) are a **static type error**, not `ANY`:
  the evaluator bails `Type Error: arithmetic requires Int or
  Float` for them (`args.rs:451-453`, pinned by
  `apply_arith(Add, string, int).is_err()`), so widening would be a
  lie — a statically-known runtime failure must fail statically.
  Overflow/division-by-zero stay runtime errors (value-dependent,
  untrackable statically — standard, not a hole).
- `CompiledMath(Vec<MathOp>)` → RPN stack simulation over inferred
  operand tags (literals push word tags, `Var` pushes env type, `Call`
  pushes return tag), operators applying the same operative rules;
  stack underflow, unknown ops, or any `ANY` operand → `ANY`.
  (Implementer confirms `MathOp` variant coverage; unhandled ops widen,
  never lie.)
- `Block(steps)` → same terminal rules as a `FUNC` body: unify
  `RETURN` paths; `RETURN`-on-some-path plus reachable fallthrough →
  error (add an explicit `RETURN ""` or restructure); no `RETURN` on
  any live path → `VOID`. `VOID` never defaults to `STRING`: assigning
  a `VOID` block to `LET $x: T` is a static error, and a `VOID` arm
  contributes no type to unification. Only explicit string contexts
  (`EXPAND`, `{{ }}` interpolation) coerce `VOID` execution to string,
  mirroring runtime.
- `Call`: host → `meta.returns`, `None` → `ANY`; script `FUNC` →
  Phase-A inferred return. **Arity** checked here (arg count known):
  mismatch = static error. Arg compatibility via `tag_assignable`
  (new helper mirroring `coerce_value` arms in `args.rs:14-71`):
  same tag ok; `STRING`→`Int|Float|Bool|Duration|Path` ok;
  expected `ANY` always ok; actual `ANY` into concrete expected =
  **error** ("bind through `LET $x: T` first" — the runtime coercion
  gate Directive 2 demands).
- `LET $x: T = <Call returning ANY>` → **allowed**: `declare_var`
  coercion is the gate. (The ANY-arg rule fires only in argument
  position, never at `LET`-RHS.)

### Terminal unification (per `FUNC` body)

- Terminal = unconditionally-executing `RETURN` / `EXIT`
  (`StaticBool(true)` counts as unconditional; every other guard is
  conditional). `EXIT` ends the path without a value (counts for
  completeness, contributes no type).
- `If`: terminal iff then-arm + every else-if + else-arm terminal
  (`else_body: None` → not terminal). `For`/`While`: **never**
  terminal (zero-trip) — a `RETURN` solely inside a loop does not
  satisfy completeness. A conditionally-guarded `RETURN` needs an
  unconditional fallback `RETURN`/`EXIT` in the same body.
- Unify all terminal `RETURN` types: same → it; any `ANY` → `ANY`;
  disjoint concrete → error naming both. Non-terminal arms (including
  `VOID` blocks and fallthrough arms) contribute no type — they only
  affect reachability for `MissingReturn`.
- **MissingReturn**: body contains a `RETURN` on some path but
  fallthrough is reachable → `bail!("function `F` may fall through
  with no RETURN ...")`.
- **VOID**: no `RETURN` on any path → `VOID` (pass-level concept, no
  new tag). `RETURN` inside a `VOID` body → error.
- `BREAK`/`CONTINUE` at function top level: neutral (runtime already
  rejects crossing); they satisfy nothing.
- `AsyncBlock`/`AssignAsync` bodies, `Timeout`/`RemoteBlock`
  wrappers, `AssignCapture` commands: traversed for nested checks;
  task values stay `ANY` (out of scope).
- `WithIo { cmd, .. }` via `walk_wrapped(cmd, ...)`: `cmd` is a
  single boxed `StepKind`, not a `Step` — the wrapper synthesizes the
  enclosing step's guard onto it and walks it as a one-step body in
  the same env, propagating returns/types. `WithIoBlock` bindings
  reference existing vars (nothing to declare).

### Unification rule (only rule, everywhere)

`unify(a, b)`: equal → it; either `ANY` → `ANY`; else error.
Custom descriptors compare by pointer identity. No bidirectional
`ANY→T` narrowing anywhere — narrowing happens solely through
runtime `coerce_value` at `LET`/`declare_var`.

## Performance guarantees (enforced, not aspirational)

- Single pass, no fixpoint: each `FUNC` body traversed once. Env
  maps fork only at `IF` arms; loops analyzed once, never iterated.
  No dataflow fixpoint anywhere in the pass.
- Env representation: eager `HashMap` clone per branch arm, matching
  the runtime's own scope semantics (`push_scope`). A parent-linked
  overlay was considered and rejected: the merge step must walk both
  arm exits to unify types regardless, so the walk is O(V) either
  way and overlays save nothing measurable while complicating
  lifetimes across the recursive traversal. Transient allocation is
  bounded by O(arms × live-vars), single-run, and strictly dominated
  by execution's own per-step map work (`declare_var` coerces and
  inserts per `LET` at runtime). Correctness-first where the cost is
  unobservable.
- Read-only: no re-parse, no re-lower, no registry writes, no I/O.
  Input is `&[Step]` + registry metas; output is `Result<()>`.
- Once per run: called from `finish_run`, never per call. Recursive
  script calls resolve to `ANY` via the in-progress set (O(1)
  membership), so inference cannot recurse with call depth.
- Hard caps, static errors (never silent truncation):
  `MAX_STATIC_DEPTH = 64` for expression nesting and nested-body
  descent; exceeding bails naming the function. Parser-bounded
  scripts never approach it; hand-built ASTs cannot wedge the pass.
- Deterministic linearity enforcement (no wall-time eyeballing, no
  Criterion — the repo has neither the dep nor a benches dir, and
  wall-timing a sub-millisecond walk under parallel CI measures
  noise): a test-only visit counter on the traversal asserts
  operations ≤ K × steps over a generated adversarial AST (deep
  `IF`/`ELSE` chains, loops, math, nested `FUNC`s). Linearity is
  proved structurally, not observed statistically. K is fixed in the
  test; exceeding it fails the suite like any regression.

## Phase G: generic type words in script declarations (build after the pre-pass)

Script `LET`/`FUNC`/`FOR`/capture annotations accept shaped
spellings (`LIST<MAP>`, `LIST<STRING>`, `MAP<name: STRING, age: INT>`,
arbitrary nesting), enforced through the existing single choke.
Records were already nameable via schemas; this closes lists and
inline records. No new DSL value syntax — declarations only.

### Structural facts (verified read-only)

- One grammar file: `crates/oxdock-parser/src/dsl.pest`; `type_tag`
  is an atomic uppercase identifier (`dsl.pest:164-167`) with zero
  `<`/`>` in any type position today. All 5 annotation sites embed it
  (`for_statement:169`, `let_statement:173`, `func_param:204`,
  `let_capture:247`, `let_async:266`).
- `parse_type_tag` (`parser.rs:1693-1697`) is a passthrough returning
  `String`; `StepKind` fields hold `decl_type: String`. The generic
  spelling therefore flows through unchanged — no `StepKind`,
  parser call-site, or handler changes.
- `resolve_tag` (`typing.rs:87-104`) is the documented single choke
  for every declaration (11 runtime sites: `define_func`, `assign`,
  all `assign_capture` paths, `dispatch_assign_async`, both
  `dispatch_await_capture` branches, `for_loop` val+key; plus the 8
  static-pass mirrors). Extending it covers every form at once.
- `TypeTag::ListOf`/`Record` + `check_value_at` already enforce
  shapes with indexed paths; `declare_var`/`mutate_var` coerce, so
  enforcement is free once resolution composes. Static pass carries
  tags opaquely (`tags_equal`/`unify` recurse). `render_tag` prints
  `LIST<MAP>`/`MAP<name: TYPE>` — generated refs stay correct.
- Record-schema infra exists but zero host crates ship one
  (`record_schemas: vec![]` everywhere); inline `MAP<...>` does not
  depend on it.

### G1 — Grammar (`dsl.pest`)

- `type_tag` becomes compound and recursive as an explicitly
  **non-atomic** rule (forcing normal implicit-whitespace handling
  even if an enclosing rule ever turns atomic):
  `type_tag = !{ type_name ~ ("<" ~ type_args ~ ">")? }`,
  `type_args = { type_field ~ ("," ~ type_field)* }`,
  `type_field = { (field_name ~ ":")? ~ type_tag }`
  (`field_name` = lowercase identifier). `!` is a valid pest rule
  modifier — `non_atomic_modifier = { "!" }` in pest_meta's own
  `grammar.pest`, alongside `_`/`@`/`$` (a review claiming otherwise
  was refuted against the vendored source; `!` doubles as negative
  predicate inside expressions and non-atomic prefix in rule
  position, unambiguous by position). At top level `!` behaves as a
  normal rule, so all spaced forms parse; determinism comes from
  canonicalization below, not rejection.
  (`MAP` fields require the colon form, `LIST` takes exactly one
  bare arg — arity/shape enforced in resolution, not grammar.)
- No conflicts: `<`/`>` never appear in type positions today, and
  ordering operators live in expression positions only.
- `FOR` key pin (`INT|STRING`, `parser.rs:1996-2007`) unchanged: a
  generic key still fails there with the existing error.
- `parse_type_tag` stays passthrough (returns the full spelling).

### G2 — Spelling model (`oxdock-parser/src/tag.rs`)

- `enum Spelled { Named(String), ListOf(Box<Spelled>),
  RecordOf(Vec<(String, Spelled)>) }` + pure
  `parse_spelling(s: &str) -> Result<Spelled, String>` (hand-rolled
  descent; grammar guarantees shape for parser strings, this keeps
  the public `resolve_tag` API safe). Whitespace is insignificant:
  the parser canonicalizes to the no-space form and interning keys
  on it, so `LIST<MAP>` and `LIST< MAP >` are one tag.
  `MAX_GENERIC_DEPTH = 8`; deeper bails naming it.

### G3 — Interning + resolution

- Composed tags need `'static` homes (`ListOf(&'static)`,
  `Record(&'static [Field])`, leaked field-name `&'static str`).
  Process-global intern table in `tag.rs`:
  `OnceLock<Mutex<HashMap<String, &'static TypeTag>>>`
  (`OnceLock` precedent: `plugin_docs()`; `Mutex` precedent in
  tests — implementer confirms `clippy.toml` allows both).
  `intern_composed(canonical, tag) -> &'static TypeTag` via
  `Box::leak`: exactly one leak per distinct spelling per process,
  bounded and documented. No `TypeDescriptor` change (lifecycle
  vtable stays clean), no `TypeTag` layout change, no enumeration
  of combinations anywhere.
- Builtin leaf consts (`STRING_TAG`, `INT_TAG`, … all 12) for
  composing references.
- `resolve_tag`: builtin → custom → **generic spelling** → schema →
  bail (schema names cannot contain `<`, so no ambiguity). Generic
  arm parses the spelling, resolves leaves through the full
  directory (so `LIST<SCHEMA_NAME>` and `LIST<CUSTOM>` work),
  composes, interns under the spelling string, returns by value.
  Signature unchanged: all 19 call sites gain generics with zero
  edits. `check_tag_known` recursion already covers composed tags.
- `DESCRIBE` param entries gain the structural string through a new
  core helper that `docs-gen`'s `render_tag` also adopts — one
  renderer, killing the second copy.
