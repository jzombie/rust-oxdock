# Plan: Network plumbing through WITH_IO pipes (LISTEN / CONNECT bridge) — Issue #159

## Goal
Enable `WITH_IO [stdin=pipe:req, stdout=pipe:resp] CONNECT <endpoint>` / `LISTEN` pattern from issue #159 with no grammar changes: bindings resolve (pipes ensured), then the bridge step dials/binds and pumps bytes bidirectionally between socket and the named pipe pair. Pipes stay byte streams; the bridge is a raw TCP socket byte pump (UDP deferred to a follow-up). No TLS handshake and no Unix-socket endpoints in the bridge: encryption above raw bytes is the caller's job, never bridge behavior.

Example targets (valid DSL only; bridge steps pump on `ASYNC` task threads, never the main flow):
```oxdock
LET $t: HANDLE = ASYNC {
  WITH_IO [stdin=pipe:req, stdout=pipe:resp] CONNECT example.com:80
}
WITH_IO [stdout=pipe:req] ECHO "GET / HTTP/1.0"
WITH_IO [stdin=pipe:resp] READ_LINE $status
AWAIT $t
```
Loopback listener (explicit port, full-duplex close choreography, see termination contract in section 2):
```oxdock
LET $ls: HANDLE = ASYNC {
  WITH_IO [stdin=pipe:req, stdout=pipe:resp] LISTEN 127.0.0.1:8080
}
LET $t: HANDLE = ASYNC {
  WITH_IO [stdin=pipe:req2, stdout=pipe:resp2] CONNECT 127.0.0.1:8080
}
WITH_IO [stdout=pipe:req2] ECHO "hello"
WITH_IO [stdin=pipe:resp] READ_LINE $got
WITH_IO [stdout=pipe:req] ECHO "back"
WITH_IO [stdin=pipe:resp2] READ_LINE $back
AWAIT $t
AWAIT $ls
```

### Load-bearing invariants (verified against code; normative for review)

The design below assumes all of these; challenging any of them requires citing the referenced code:

- Pipe EOF requires `closed:true`. `PipeInner::read_into` returns `0` only when `state.closed` is set on an empty buffer, otherwise it blocks on the condvar (`crates/oxdock-core/src/exec/pipe.rs:197-215`). `closed` starts `false` (`pipe.rs:106-115`) and is set only by writer/keeper drop when counts hit zero (`pipe.rs:155-187`). Corollaries: a fresh pipe with no writer blocks (never spuriously EOFs); no transient writer touches a stdin-bound pipe before its producer step runs; pre-allocating keepers on *consumed* pipes is forbidden (it would suppress genuine stdin EOF and hang pumps).
- `AWAIT` on a failed task propagates its error and aborts the step (`exec/handlers.rs:2893` `await_task_entry`): no fall-through past failure, so guards like `IF $addr == "" { AWAIT $ls }` cannot slide into downstream steps.
- `ThreadJoinHandle::kill` joins the task thread (`exec/steps.rs:95-107`): any uninterruptible block (accept/recv/pipe-read) hangs `CANCEL` and teardown, hence the tick-bounded cancel loops and supervisor below (no notify-dependent wakeups remain in the design).
- The root end-poll reaps un-awaited named tasks (`exec/steps.rs:868-887`): task lifetime never exceeds the run.
- Runtime `==`/`!=` fall back to string comparison for non-numerics (`exec/args.rs:523-533`): the empty-addr guard is expressible with existing syntax.
- `READ_LINE` strips trailing line endings (`exec/handlers.rs:679-721`): announced addresses arrive clean; CONNECT-side trim is defense in depth.
- `LET`-capture owns stdout and parse rejects `WITH_IO` stdout pipes in captures (`parser.rs:1095` `reject_pipe_stdout_in_capture`): combined with the absence of any task-metadata surface, this is why v1 requires explicit ports instead of discovery.
- First binding wins on pipe type (`exec/io.rs:188-217` `ensure_pipe_for`): OS-promoted vs script pipes resolve deterministically regardless of task spawn order.

## Proposed approach
### 1. Command surface (parser)
- Add `LISTEN` + `CONNECT` leaf commands in `crates/oxdock-parser/src/commands.rs` via `declare_commands!`.
- v1 spelling (raw TCP socket bridge, accept-one; accept-loop deferred; no `--tls`/`--unix`; UDP deferred to a follow-up, see Decisions):
  - `CONNECT <host:port> [--timeout <dur>]` rides ambient `WITH_IO` bindings (no grammar change): `WITH_IO [stdin=pipe:req, stdout=pipe:resp] CONNECT ...`. Must run inside `ASYNC` (enforced, see section 2). Rejects bare use without `WITH_IO` pipe bindings with a step-numbered error. Endpoint strings are trimmed before resolution (defense in depth; `READ_LINE` already strips line endings).
  - `LISTEN [host:]port` rides ambient `WITH_IO` bindings like `CONNECT` (no positional pipe args: pipes stay structural `IoBinding` nodes, never ad-hoc `"pipe:"` string parsing in core): `WITH_IO [stdin=pipe:req, stdout=pipe:resp] LISTEN 127.0.0.1:8080`, always inside `ASYNC` (same enforcement as `CONNECT`). Then accept-one+pumps. Explicit ports only: ephemeral (`0`) or omitted ports are rejected with a step-numbered error (dynamic discovery needs task-handle metadata that does not exist yet; revisit then). An omitted host defaults to `127.0.0.1` (never `0.0.0.0`); non-loopback hosts and `0.0.0.0` rejected. Bind failures surface directly: the task errors and `AWAIT` raises the root cause (pinned by `listen_bind_conflict`).
- Add `CommandMeta` with syntax/summary/examples (doctests must compile; use `oxdock!` macro form, `indoc` raw blocks).
- Parser tests in `commands.rs` + `parser/src/lib.rs` for lowering and Display round-trip.

### 2. Execution (oxdock-core)
- New module `crates/oxdock-core/src/exec/net_bridge.rs` (or `bridge.rs`). A synchronous pump on the main sequential flow deadlocks (it blocks on `stdin` in `PipeInner::read_into` while producer steps wait behind it), so both commands are background-only when bound to script pipes:
  - `CONNECT`: dials synchronously (fail fast on refused/timeout), then pumps on the calling thread, which must be an `ASYNC` task thread. Enforced: `WITH_IO`-pipe-bound `CONNECT` outside `inside_async` bails with a step-numbered error pointing at `LET $t: HANDLE = ASYNC { ... }`. Reuses existing machinery untouched: keeper pins (`pin_async_keepers`, produced pipes only, per the invariants above), `AWAIT`/`CANCEL`/`TIMEOUT`, and the shared `PipeRegistry` across threads. Each pump direction ends on its own EOF/close/cancel (see pump lifecycle below); the task ends when all its threads are done; `AWAIT` reaps it.
  - `LISTEN`: binds synchronously on the task thread (fail fast on non-loopback host, `0.0.0.0`, or ephemeral/omitted port), then accept-one+pumps under that same task lifetime. No threads escape the task: direction workers and the acceptor are spawned and joined inside it, so lifetime is the `ASYNC` task lifetime, managed by `AWAIT`/`CANCEL`/`TIMEOUT` plus the root end-poll that reaps un-awaited named tasks (`steps.rs:868`). Nothing outlives the run; nothing needs a second handle.
  - `pump(stdin, out, socket)`: two direction worker threads joined by the task thread (internal threads never outlive the task, so lifecycle is unchanged): stdin-pipe->socket and socket->stdout-pipe. Each direction blocks naturally (pipe `read_into`, socket `recv`/`send`): no hot-path polling, no interleave latency. Direction lifecycle: stdin EOF -> `shutdown(Write)` + exit that directional loop (a closed+empty pipe returns `0` without blocking, so the loop MUST exit or it spins); the task continues the socket->stdout direction until socket close. On any natural EOF or error, directions do not signal each other (each waits on its own source, which still signals; cross-notify was considered and deleted as purposeless) — the sibling continues per half-close design unless its own end condition holds. EOF is terminal per direction: the bridge never depends on pipe resurrection. Socket close -> pipe EOF (drop `PipeWriter`). Teardown suppresses the peer-gone error class (`ENOTCONN`/`ECONNRESET`/platform equivalents) from `shutdown`/close: a dead peer is routine, not a task failure. Termination contract: a session ends only when every pump stdin pipe reaches EOF, so scripts must choreograph both directions (full-duplex example above); an input pipe that never gets a writer blocks that direction indefinitely by design. Ordering rule: the main thread must complete all producer steps before `AWAIT`ing a bridge task (all reference patterns obey this); `AWAIT`-before-produce deadlocks by construction, exactly like awaiting any task whose input you have not sent yet. Long-lived sessions are bounded with `TIMEOUT <dur> AWAIT $t`, which cancels through the same supervisor path. Worker errors (e.g. socket `recv` reset) tear down the whole task: the supervisor cancels siblings, closes the socket, and returns the error for `AWAIT`. A clean peer FIN ends only the socket→stdout direction: stdin→socket persists by half-close design until stdin EOF, `TIMEOUT`, or `CANCEL` (a peer that half-closes then keeps reading is legitimate TCP; cross-killing the stdin direction on socket EOF would break its uploads and is explicitly rejected). The pump moves raw bytes with zero text interpretation, so it can carry SSH: tunnel bytes flow bridge<->pipes<->`RUN ssh`.
  - Peer-FIN trace (normative; walk it instead of asserting it): peer clean-FINs → T_out `recv` 0 → drops stdout writer → exits Ok. Supervisor tick: T_out done, T_in alive, token unset → steady state, keep ticking (the session persists: correct half-close behavior, not a hang). Producer EOFs stdin → T_in `shutdown(Write)` + exits direction → full close → both workers done → task completes → `AWAIT` returns. Cancel at ANY point → token path: notify + socket shutdown → both workers exit → bounded join, no live worker is ever block-joined. Error (RST) at any point → whole-task teardown for `AWAIT`. Single-worker exit is steady state, never a teardown trigger and never a join target: no interleaving of these events produces a hang.
  - Cancel-aware blocking (no uninterruptible waits, no poll-driven hot path): the task thread supervises (resolved pipe names + a `PipeRegistry` clone for one-time setup): it spawns the two direction workers plus, for `LISTEN`, one acceptor thread doing blocking `accept` (zero handshake latency), then ticks at ~10ms like `AWAIT` itself does, checking completion (`is_finished`-style polling, never a blocking join on live workers) vs the task `cancel_token` (already in `StepCtx` via the forked state). Joins happen only on the teardown path after notify+shutdown, so a legitimately persisting direction can never wedge the supervisor; the teardown join is bounded by design. Workers run a fixed loop of timeout-bounded-read (~10ms backstop) → token-check → act (never bare blocking `read_into`): wakeups are time-driven and un-losable, so cancellation resolves within ~one tick with no notify machinery and no `PipeInner` predicate changes (an earlier notify-based design was deleted precisely because notify-without-predicate-change re-sleeps). No notifier handles and no registry lookups on any path: the backstop tick is the only wakeup source besides data and close. On cancel the supervisor shuts down the connected socket, then joins everything boundedly (workers exit on their next tick-or-traffic wake, whichever comes first). The acceptor runs non-blocking with a short poll tick checking the token (~1ms Unix, ~16ms Windows to match scheduler granularity): worst case is that much one-time handshake latency, stated honestly, and the data path is unaffected (blocking pump, zero added latency). Idle cost is one non-blocking `accept` syscall per tick — negligible by the numbers. (`set_read_timeout` cannot do this job: it does not affect `accept()` on major platforms, so the tick stays.) A client arriving during `CANCEL` is dropped at the next tick, which is correct abort semantics. Pipe reads use the timeout-bounded `wait_timeout` read in `pipe.rs` with a ~10ms backstop (bridge-only caller; existing `read_into` semantics stay unchanged for all DSL readers). Worst-case `CANCEL` latency is ~2-3 ticks (~30ms) + scheduling: supervisor tick + worker backstop + join. Steady-state idle cost is trivial by the numbers (order-of): ~100 timeout-wakes/sec per pump direction and ~1000 non-blocking accepts/sec per idle listener, each sub-microsecond — well under 0.1% of a core even with several concurrent bridges; the data path itself never polls. This is required because `ThreadJoinHandle::kill` joins the thread (`steps.rs:95`): an uninterruptible `accept()` or `recv()` would hang `CANCEL`, cancel-teardown, and the root end-poll.
  - Scope policy (resolves the `example.com` vs loopback tension in #159, where the loopback rule constrains binds, the listener threat): `LISTEN` binds loopback-only, explicit ports only (ephemeral rejected: no discovery channel exists yet; revisit with task-handle metadata). `CONNECT` may dial loopback or remote hosts (outbound dialing is `RUN curl`-equivalent, not a listener threat). The environment must support loopback TCP (tests and local halves depend on it).
  - Privilege gate (shape open for discussion): the bind policy above always applies; gate availability itself behind a privileged-primitive-style env/flag (exact name TBD during implementation).
- EOF/close mapping in `io.rs`/`pipe.rs`: ensure dropping bridge writer triggers `detach_writer` -> closed -> readers see 0 (already exists); add explicit `close`/`shutdown` path for socket half-close; define backlog ownership (bridge holds one writer attachment per direction; no keeper pins beyond pump lifetime).
- UDP deferred to a follow-up: byte-stream pipes cannot preserve datagram boundaries (read chunking is scheduling-dependent), and wire framing was already rejected as protocol corruption. The follow-up designs pipe-side datagram mapping explicitly. v1 is TCP-only; the parser accepts no `--udp` flag.
- Explicit non-goals: TLS termination/handshake in the bridge (caller's job over the raw byte stream) and Unix-socket endpoints (deferred; TCP loopback covers the #153/#158 local halves for v1).

## Reference composition: local SSH proxy (validates the design end to end)

```oxdock
LET $listener: HANDLE = ASYNC {
  WITH_IO [stdin=pipe:remote_to_client, stdout=pipe:client_to_remote] LISTEN 127.0.0.1:2222
}
LET $remote: HANDLE = ASYNC {
  WITH_IO [stdin=pipe:client_to_remote, stdout=pipe:remote_to_client] RUN ssh -W target-internal:22 user@bastion-host
}
AWAIT $listener
AWAIT $remote
```

Why this is sound under the plan (checked, not assumed):
- Fixed loopback port; no discovery step exists or is needed.
- No premature EOF: both pumps hold a writer attachment per direction for task lifetime, and fresh pipes start `closed:false`, so readers block until bytes arrive regardless of spawn order (safety comes from writer attachments + initial state, not keeper timing). First-binding-wins is order-independent here: OS-promoted or script pipes both route correctly, and each pipe end is taken exactly once.
- Session ends coherently: client disconnect -> accept-one pump drains -> writers drop -> EOF propagates -> `ssh -W` exits on stdin EOF -> tasks complete; `CANCEL`/abort flows through the token-polled loops.

## Decisions (user-confirmed)
- Scope v1: raw TCP socket bridge only, explicit loopback ports only. No TLS in the bridge (encryption is the caller's job); no Unix-socket endpoints; UDP deferred (byte-stream pipes cannot preserve datagram boundaries; wire framing already rejected as corruption; pipe-side datagram mapping is a follow-up design). Ephemeral rejected (no discovery channel; revisit with task-handle metadata). Single-connection accept-one for LISTEN; accept-loop deferred.
- Port discovery: deleted (user scope cut). No announce channel, no guard pattern, no meta pipe. Rationale: stderr-as-IPC overloads diagnostics, and the grammar has no task-metadata surface; ephemeral returns only with native task metadata. CONNECT returns nothing (pumps to completion/cancel).
- Execution model: background-only pumps. `CONNECT` runs inside `ASYNC` (misuse bails, never hangs); `LISTEN` binds sync on the task thread (explicit ports only, no discovery).
- Applies code-review findings round 1: sync-pump deadlock (background model + `bridge_sync_bail`), invalid example syntax (`FROM` clause and file-oriented `WRITE pipe:req` replaced with `WITH_IO` + `ECHO`/`READ_LINE` patterns), bind-vs-dial scope split (`LISTEN` loopback-only, `CONNECT` may dial out), no UDP wire framing.
- Round 2 dispositions: premature-EOF claim rebutted (`PipeState` starts `closed:false`, so `read_into` blocks until genuine data-or-close; pinning keepers on consumed pipes would suppress real stdin EOF and hang, so explicitly not done; `connect_roundtrip` ordering pins it). `LISTEN` leak fixed by deleting the unmanaged spawn: `LISTEN` pumps on its `ASYNC` task thread with addr announced on bound stderr, lifetime inherited from task reaping. Positional pipe args deleted: `IoBinding`-only. Ephemeral-only relaxed: explicit loopback ports allowed.
- Round 3 dispositions: EOF-race claim rebutted again on verbatim code (EOF requires `closed:true`, set only by writer/keeper drop; a never-written pipe blocks; pump never exits on stdin EOF so late producers are safe; consumer-side keepers stay rejected). Stale capture-var discovery line removed: stderr-announce is the single mechanism. Blocking-`accept` accepted: accept/pump loops are cancel-aware (non-blocking sockets, token-polled ticks, timeout-bounded pipe read in `pipe.rs`) because `kill()` joins (`steps.rs:95`); `bridge_cancel` pins it. Stderr-announce kept with exactly-one-line + post-announce silence + EOF-means-bind-failed rules (return-value alternatives need new surface). UDP deferred to a follow-up (neither wire framing nor scheduling-dependent chunking is acceptable).
- Round 4 dispositions: unwritten-pipe example deadlock accepted and fixed at the source (loopback example is now full-duplex with choreographed close; termination contract documented: every stdin pipe must reach EOF, unwritten pipes block by design). Stderr failure cascade acknowledged; fixed by failure contract (bind failure -> meta EOF + task error via `AWAIT`, never dial an empty addr; `listen_bind_failure` pins root-cause surfacing) with no new surface. Teardown suppression specified for the peer-gone error class with mock-covered unit test.
- Round 5 dispositions: spin-loop accepted (directional loop now exits on stdin EOF after half-close; the task persists for the socket direction; "late-producer safe" removed, EOF terminal per direction). Single-thread polling replaced with two blocking direction threads joined by the task thread (lifecycle unchanged); only the idle accept loop polls, and the pipe timeout tick is a long-interval cancel escape. Discovery cascade answered with existing syntax (runtime `==` string fallback verified in `args.rs:523`; guard pattern + `listen_bind_failure` pin it; new-surface alternatives stay rejected). Teardown suppression and termination contract stand.

String-keyed notify replaced with one-time `Arc<PipeInner>` notifier capture (direct condvar signaling; registry untouched on hot path).
