# Plan: Variable-scoped pipes + host pipe API + parser error attribution

## Goal
1. Remove `pipe:name` entirely. Pipes become values owned through variables
   only: `LET $p: PIPE` mints a fresh anonymous backend, `WITH_IO [stdin=$p]`
   uses it, and no syntax names a shared channel anymore.
2. Enable pipes to be sent to Rust functions: host fns read bytes, write
   bytes, and mint fresh handles to return, via a new public API.
3. Enable Rust functions to be producers of pipe material: mint fresh pipe
   handles to return, and write bytes into caller-provated pipes.
4. Fix parser error misattribution: nested-step syntax errors must point at
   the failing line with the specific reason, never at the enclosing block.

## Non-goals
- No `poll`/`select` surface, no datagram work, no TLS (unchanged).
- Single-connection bridge pump semantics untouched (plumbing identity
  changes only, not pump behavior).

## Decisions (user-confirmed)
- Declaration syntax: bare `LET $p: PIPE` (no initializer). No trailing
  `;` needed: semicolons only separate same-line statements, per existing
  DSL convention. New grammar required (`let_statement` today mandates
  `= expr`).
- Host ops: read + write + mint fresh handles.
- Removal: every position at once (bindings, `pipe:` expressions, assert
  targets, INSPECT-by-name, docs, fixtures). No phased literals.
- OS pipes: kept, rekeyed from names to backend handles.
- Materialization: lazy at first binding, not eager at declaration
  (eager pre-commits backend type with zero usage context).

## Design

### 1. Backend ownership (revised: lazy, owned, registry-free)
`PipeValue` holds `Arc<OncePipe>` where `OncePipe` starts unbound and
materializes on first binding — never eagerly at declaration. Rationale:
eager minting pre-commits a backend type with zero usage context (a later
RUN-terminated binding would find the wrong kind), while lazy defers the
decision to the first binding site, which has full context (RUN-terminated
⇒ OS, else script — same rule as today). `PartialEq` via handle identity,
`Display` renders opaque `<pipe>`.
- No central index: resolution, INSPECT, ASSERT, and keepers all operate
  on handles already in hand (`OnceLock` makes first-binding atomic
  across threads; concurrent first-binders resolve identically through
  the existing adapters either way). `PipeRegistry`'s lookup role is
  deleted, not rekeyed — if deletion proves risky mid-implementation,
  fallback is a thin id-keyed index, never a name map.
- Unbound handles report kind `unbound` (buffered 0); `LET $q: PIPE = $p`
  clones the handle (shared backend, natural fan-out semantics for
  explicit sharing).
- Lifetime falls out of ownership: last drop closes; keepers become
  plain backend clones held to expiry (plus a no-resurrect attach for
  the gap pins, preserving the never-resurrect-EOF invariant).
- `Value::pipe(name)` dies; `Value::pipe_fresh()` mints unbound handles
  for bare `LET` evaluation and for Rust callers. Backend relocation
  target unchanged (`oxdock-process`, verified edge or micro-crate).

### 2. Grammar (`crates/oxdock-parser/src/dsl.pest`, `parser.rs`, `ast.rs`)
- `let_statement` gains a bare-declaration form: `LET $p: PIPE` (no `=`,
  no `;` required). Evaluates to a fresh backend bound to the variable.
  `LET $p: PIPE = <expr>` keeps working for copies/returns.
- Delete the literal: `pipe_binding` rule becomes `$var`-only;
  `pipe_read` expression rule removed; `PipeTarget::Name` deleted
  (`PipeTarget` collapses to a variable wrapper or dies entirely —
  implementer's choice, but no name-carrying variant survives).
- `AssertTarget::Pipe(name)` becomes variable-based; `LET`-capture and
  `reject_pipe_stdout_in_capture`-style rules stay structurally identical,
  operating on variables.
- `Command::is_statement_keyword`, `fmt_io`, `emit_io_bindings`,
  `parse_io_binding`, and Display arms updated; unknown `pipe:` text
  becomes a pointed parse error naming the migration
  (`pipe:name was removed; declare LET $x: PIPE and pass $x`).

### 3. Runtime (`crates/oxdock-core/src/exec/`)
- No name-keyed maps: resolution takes the backend out of the `PIPE`
  value (`OnceLock`-initialized on first binding if still unbound).
  First-binding-wins survives in its correct, narrow form (one handle,
  one decision) instead of as a global race.
- Keepers: kept as backend clones (plus no-resurrect attach), keyed by
  handle, released at existing expiry points. Transient-gap protection
  is orthogonal to naming; owned lifetimes do NOT replace keepers (a
  held variable keeps the backend alive, but zero-writer gaps between
  producer steps still need pins — unchanged semantics).
- Take-once OS slots, `bridge_os_*`, direct-vs-bridged split: preserved,
  keyed by backend object instead of name (slot state travels with the
  backend, not an index). The recycling fix survives verbatim.
- `out_pipe_name`-style enrichment becomes the backend `Arc` directly
  (simplifies the bridge: no lookup at all).
- `INSPECT($p)` unchanged (already variable-based; gains the `unbound`
  kind pre-binding).

### 4. Host API (read / write / mint)
- New public API for stateful host fns (Pure fns have no `cx` and stay
  byte-blind): on `ExecState` (or `StepCtx` public methods —
  implementer's choice, one surface only):
  `pipe_reader(&Value) -> Result<SharedInput>`,
  `pipe_writer(&Value) -> Result<SharedOutput>`,
  `new_pipe() -> Value`, plus `close_pipe(&Value)`.
- Streaming contract (normative, not `Vec<u8>` anywhere): all byte
  movement is slice-based through the standard traits —
  `Read::read(&mut [u8]) -> Result<usize>` and
  `Write::write(&[u8]) -> Result<usize>` on caller-owned buffers, `0`
  read means EOF exactly like `std::io`. No per-chunk heap allocation
  is imposed by the API; buffer reuse is the caller's. A host fn that
  tried to slurp a stream into one `Vec` would inherit unbounded
  memory growth — document against it, don't enable it.
- Standard-trait adapters: a thin `PipeStream` wrapper (reader and/or
  writer half, borrowed from the call context) implementing
  `std::io::Read` + `std::io::Write` by delegating to the slice
  primitives, so host fns can hand pipes directly to `serde_json`,
  `flate2`, `tar`, and friends. `flush()` is a pass-through no-op
  unless the backend is a kernel stream.
- Document blocking semantics (a host read blocks the task thread like
  any DSL reader), EOF/half-close mapping (same as DSL consumers), and
  Miri (socket-backed handles stay `cfg_attr(miri, ignore)`-gated
  in tests).
- `#[oxdock_func]` needs no macro change if PIPE params already arrive
  as `Value` (verify during implementation; extend only if the macro
  rejects unknown param types).
- Host-constructed backends participate in keepers/promotion exactly
  like script-created ones (same code paths, owned handles).
- `new_pipe()` returns an unbound handle (lazy, like bare `LET`); reads
  and writes behave identically pre/post materialization.

### 5. Parser error attribution (from `scripts/proto.echo-listen.oxdock`)
- Repro (in tree): line 23
  `WITH_IO [stdin=pipe:resp, stdout=pipe:req] ASYNC CONNECT 127.0.0.1:{{ $orb_port }}`
  fails, but the reported error blames `WHILE true` instead of naming
  line 23 with the specific reason.
- Methodology is reproduction-first: add a parser unit test feeding the
  exact script and printing the actual error before concluding anything.
  Unverified hypotheses to check, not assertions: (a) mixed
  `host:{{ var }}` argument handling inside compound-atomic spans
  (`async_statement` is `${...}`; inner pairs collapse and the command
  is re-parsed from text); (b) error-span attribution: when an element
  inside a block fails, the failure surfaces at the enclosing
  `while_statement` span instead of the failing element's span
  (suspects: `refine_span`/`SpanContext` construction,
  `parse_pest_error` outermost-rule reporting, `classify()` keyword
  mapping in `commands.rs`).
- Constraints on the fix (do not bulldoze these): compound-atomic rules
  still yield inner pairs for named subrules (the parser matches on them
  today), and Pest errors carry spans — the defect is in our span
  selection, not pest capability. Atomicity exists to suppress implicit
  whitespace in nested contexts; any de-atomization must be targeted at
  exactly the failing rules with the full grammar test suite green, not
  a blanket removal.
- Acceptance: the error names line 23 plus the specific reason
  (whatever it proves to be: unsupported composition, bad argument,
  or a validity rule); every valid form — including mixed
  `host:{{ var }}` templates and nested `WITH_IO`+`ASYNC` — parses;
  regression tests pin both the message text and the reported line.
  Valid scripts must keep parsing; only the attribution changes.
- Likely files (confirm during implementation):
  `crates/oxdock-parser/src/parser.rs` (block/element error paths),
  `crates/oxdock-parser/src/dsl.pest` (block/element rules),
  `crates/oxdock-parser/src/commands.rs` (`classify()`),
  `crates/oxdock-parser/src/error.rs` (`SpanContext`, error kinds).

### 6. Migration (mechanical, in this order)
1. Parser: grammar + AST + lowering + Display + unit tests (incl. the
   error-attribution regression tests from section 5).
2. Value model + backend relocation.
3. Core runtime rekey (registry, resolve, keepers, bridge, OS paths).
4. `oxdock-macros` emit paths, `oxdock-build` track arms.
5. Fixtures: every `pipe:name` → `LET` + `$var` (~98 hits, mostly
   `WITH_IO` bindings; assert targets and `pipe:` expressions too).
   Parity fixtures (`dsl.txt` + `tokens.rs` pairs) and
   `buildtime_macros` embedded scripts included.
6. Docs templates + `docs-gen` regen (reference examples rewritten;
   `pipe:<name>` prose replaced with the declaration pattern).
7. Full suite green after each batch; `coverage.toml` needs no new
   kinds (no `StepKind` changes expected).

## Tests (new behavior pins)
- Bare `LET $p: PIPE` declares an *unbound* handle (`INSPECT` kind
  `unbound`); first binding materializes it (script backend, or OS for
  RUN-terminated first bindings).
- `pipe:name` anywhere is a pointed parse error (literal in bindings,
  expression, and assert positions).
- Isolation: two modules/cases using the same old literal name share
  nothing (regression test for the original complaint).
- Loop generations: re-declaring per iteration yields independent pipes.
- Host round-trip: Rust fn reads bytes written by DSL, writes bytes DSL
  reads, returns a fresh handle the DSL can bind (mock-process
  harness; socket-backed variants Miri-ignored with reasons).
  Streaming shape pinned: host side drives a single reused stack buffer
  through the `Read`/`Write` adapters (no `Vec` slurp anywhere in the
  path), including one adapter-fed `serde_json`-style std consumer.
- OS promotion still triggers for RUN-terminated bindings (existing
  `os_pipe_pair` fixture migrated to variables).
- Existing semantics preserved: full-duplex round-trips, EOF mapping,
  cancel bounds, proxy termination (re-run, not rewrite, of the
  bridge suite).
- Parser errors: exact-script regression test naming line 23 plus the
  verified reason; valid nested forms parse.
