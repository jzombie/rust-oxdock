# Plan: NET plugin module replacing CONNECT/LISTEN + plugin docs

Decisions (user-confirmed): SSH-mirror API, hard removal of CONNECT/LISTEN,
ssh-style `net` feature flag, both docs approaches (per-plugin README plus
auto-rendered plugin section).

## Part 1: New `oxdock-net-plugin` crate

Scaffold `crates/plugins/oxdock-net-plugin/` as a copy of the SSH plugin
shape (`Cargo.toml`, `src/lib.rs`, `src/funcs.rs`, `src/bridge.rs`,
`src/validate.rs`, `src/state.rs`, `tests/integration.rs`,
`tests/integration/net.rs`):

* `NET_SERVE(bind: String)` stateful: `TcpListener::bind` on loopback,
  returns `MAP {listener: NET_LISTENER, addr: STRING}`. Listener handle is
  a new `#[oxdock_type(name = "NET_LISTENER")]` opaque tag wrapping
  `Arc<ListenerState>` (mirrors `SshServerTag` at
  `crates/plugins/oxdock-ssh-plugin/src/types.rs:19`), so ACCEPT/CLOSE can
  consume it and shutdown stays idempotent via `Drop`.
* `NET_ACCEPT(cx, listener: Value, in_pipe: Value, out_pipe: Value)`:
  accept-one then delegate to the pump. Must enforce
  `cx.is_async_task()` with the same bail text pattern as
  `funcs.rs:189-193` in the SSH plugin.
* `NET_CLOSE(listener: Value)`: pure shutdown, returns BOOL.
* `NET_CONNECT(cx, target: String, in_pipe: Value, out_pipe: Value)`:
  `TcpStream::connect_timeout`, then pump.
* `NET_PUMP(cx, from_pipe: Value, to_pipe: Value)`: reuse the exact
  `pump_pipe_to_pipe` pattern (`bridge.rs:243-282`).
* Pipe handling: resolve `SharedInput`/`SharedOutput` on the supervisor
  thread only via `cx.pipe_reader` / `cx.pipe_writer` / `cx.close_pipe`
  (`crates/oxdock-core/src/exec/steps.rs:367-458`); never cross threads
  with `&StepCtx`. Poll `cx.is_cancelled()` in pump loops.
* Reuse the TCP pump core by moving `crates/oxdock-core/src/exec/net_bridge.rs`
  pump workers (`pump_in`, `pump_out`, `pump`, `CHUNK=8192`, tick
  constants) into the plugin crate as `bridge.rs`, adapted from ambient
  `StepCtx.stdin/out` to explicit pipe `Value` args. Keep loopback-only
  bind validation and `--no-half-close` semantics as an options MAP
  (`NET_SERVE(bind, {})` / `NET_CONNECT(target, in, out)` stay fixed-arity;
  half-close flag rides the trailing MAP like SSH `key_path`).
* `module_with::<P: ProcessManager>()` plus `module()` pinning
  `DefaultProcessManager` (mirror `funcs.rs:341-354`).
* Tests mirror `tests/integration/ssh.rs`: `run_script` helper registering
  only the NET module, `indoc!` scripts with `IMPORT [STD, NET]`,
  raw `std::net::TcpListener`/`TcpStream` peers, every e2e test carrying
  `#[cfg_attr(miri, ignore = "needs loopback TCP plus threads")]`.

## Part 2: Hard removal of CONNECT/LISTEN

* Parser: delete `Connect`/`Listen` variants and lowering closures in
  `crates/oxdock-parser/src/commands.rs:1299-1427`, `Command::Connect/Listen`
  in `ast.rs:43-134`, `Display` arms at `commands.rs:2405-2428`, and
  `default_output` entries. Old scripts then fail at parse with unknown
  instruction. No PEG rule exists, so `dsl.pest` is untouched.
* Core: delete `crates/oxdock-core/src/exec/net_bridge.rs`, dispatch fns
  `dispatch_connect_step` / `dispatch_listen_step`
  (`handlers.rs:427-462`), `define_pipeline!` arms (`lib.rs:43-44`), and
  the `steps.rs:713-737,989-1013` match arms.
* Tests: delete parser lowering tests (`commands.rs:2589-2663`), bare-pipe
  composition test, `net_bridge.rs:494-580` units, and core bridge
  integration tests (`exec/tests.rs:2656-3732` plus helpers at
  `2666-2731`). Migrate the proxy/echo coverage to NET plugin e2e tests.
* Update `proto.echo-listen.oxdock` and any docs fragments referencing
  CONNECT/LISTEN to NET module calls.

## Part 3: Feature wiring (mirror SSH exactly)

* Workspace `Cargo.toml`: `oxdock-net-plugin = { path = ... }` member entry.
* `oxdock-cli/Cargo.toml`: `net = ["dep:oxdock-net-plugin"]`, optional dep.
* `oxdock/Cargo.toml`: `net = ["cli", "oxdock-cli/net"]`.
* `oxdock-cli/src/lib.rs:28-49`: extend `cli_host_modules()` /
  `cli_host_types()` with `#[cfg(feature = "net")]` arms returning the NET
  module and `NetListenerTag::descriptor()`. Add feature tests mirroring
  `ssh_feature_serves_and_closes` / `ssh_scripts_rejected_without_feature`
  (`lib.rs:824-878`).

## Part 4: Plugin documentation

* Per-plugin README: create
  `crates/plugins/oxdock-net-plugin/.oxdock/template/` (`values.json`,
  `header.md.tmpl`, `README.md.tmpl`, `fragments/*.md.tmpl`) plus
  `target.json` with a globally unique target name; add the same for the
  existing SSH plugin (it has none). Hand-write `### NET::SERVE`-style
  sections mirroring `render_function_reference` style
  (`Signature`, `Contexts`, summary/docs from `#[oxdock_func]` attributes).
  Existing `scopes` in `docs-gen.json` already cover `crates/**/target.json`.
* Auto-render: extend `crates/docs-gen/src/oxdock/command_ref.rs`
  `render_function_reference()` to also render registered plugin modules
  (feed each plugin `HostModule`'s `FuncMeta` list alongside
  `builtin_function_metas()`), so `function-reference.md.tmpl` gains
  NET/SSH sections without hand duplication. Keep `COMMAND_INDEX` /
  `COMMAND_BODY` STD-only.
* Regenerate with `cargo run -p docs-gen`, commit templates plus outputs.
  Never edit `README.md` or `generated/*.md.tmpl` by hand. New fragments
  follow prose rules: no em/en dashes, `\{{ ... }}` escaping, every Rust
  fence runnable as doctest, DSL examples via `oxdock!` + `indoc`.
