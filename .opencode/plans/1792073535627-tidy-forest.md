# Issue 223 Investigation Plan: SSH exec byte-faithfulness + proxy example

## Context
- Issue: https://github.com/jzombie/rust-oxdock/issues/223 (open, `bug`). Verified on `v0.28.0-alpha` Windows MSVC binaries.
- Prototype: `scripts/proto.ssh-proxy.oxdock` (94 lines, header says throwaway, should become example). Accept loop: `SSH_SERVE` -> `SSH_DEQUEUE` -> `SEMAPHORE_TRY_ACQUIRE` admission -> per-session `ASYNC` worker with `ENV SSH_USER/SSH_CLIENT/SSH_SERVER` relay -> `SSH_PTY_RUN($sess.session, ["ssh","-o","BatchMode=yes","orb"],...)` + `SSH_PUMP_CHANNEL`, `AWAIT` both.
- User scope: full issue including races. Windows box available for repro.

## Verified findings (from code exploration)
- `SSH_PTY_RUN` path: `crates/plugins/oxdock-ssh-plugin/src/funcs.rs:656-694` (`ssh_pty_run`) -> `crates/plugins/oxdock-ssh-plugin/src/pty.rs:282-359` (`pump_pty_session`). Uses `portable-pty 0.9.0 CommandBuilder` (`new(argv[0]) + args(argv[1..])`), no in-repo join. Unix: `execvp` verbatim. Windows: `cmdbuilder.rs:668-745 append_quoted` (MSVCRT `ArgvQuote`: quote iff empty or `[ \t\n\x0b"]`, `"` as `\"` with `2n+1` backslashes, trailing `\` doubled) -> `CreateProcessW` in `win/psuedocon.rs:113-174`. No `%` handling in spawn path.
- Interpolation: `crates/oxdock-parser/src/parser.rs:3524 parse_quoted_string` passes literals verbatim; `crates/oxdock-core/src/exec/args.rs:1466 expand_string` single-pass (escapes `\\ \{{ \n \t \r \"` on template bytes only, values via `push_str` verbatim, never rescanned). `ENV` (`handlers.rs:3106 dispatch_env`, `steps.rs:751`) and `ECHO` resolve once. So Bug 2 as described (value unescape) is NOT visible in current `expand_string`; needs live repro to locate second-pass or client-side confound.
- SSH pump: `auth.rs:127-135 exec_request` stores `String::from_utf8_lossy(data)` verbatim in `PendingSession`; `funcs.rs:108 ssh_dequeue` exposes `command/username/addr` verbatim. `bridge.rs:172 pump_session`, `pty.rs:205 pump_master_in / 125 pump_master_out`. No `exit-status`/`ExitStatus` send in `oxdock-ssh-plugin/src/*`; `runtime.rs:164-184` drops `ExitStatus/ExitSignal`. PTY path returns local code as `SSH_PTY_RUN` INT only.
- Existing relay tests: `crates/plugins/oxdock-ssh-plugin/tests/integration/ssh.rs:569-640` (`pty_child_sees_session_env_unix/windows`), `TestClient::connect_impl:272-287` waits for `pty+exec/shell Success` acks before returning.

## Plan
1. Repro harness on Windows box (author supplies host):
   - Map service (`oxdock -p <host_port>:ssh-server`), run `scripts/proto.ssh-proxy.oxdock` variant with `od -c` receiver.
   - Case A (Bug 1 argv): `SSH_PTY_RUN($sess.session, ["cmd.exe","/c",$sess.command],...)` with `echo "foo bar"`, `reg query "HKLM\SYSTEM\Setup" /v SetupType`, `%`/`%%` + `call echo [%VAR%]` probes.

   - Case D (stdin race): fresh `request_pty+request_shell`, type `exit` immediately after prompt; count `xit` occurrences; also probe output-side trailing-newline loss (`0x0[OOBE]` glue).
2. Root-cause once repro data in:
   - Bug 1: confirm `append_quoted` MSVCRT output vs `cmd /c` parsing (cmd does not understand `\"`; outer-quote stripping rules). Decide: document `cmd /c` needs single-string payload + `cmd`-compatible escaping vs add `SSH_PTY_RUN` cmd-aware mode or pty-less exec path. Check `%` doubling source (spawn vs cmd vs client).
   - Bug 2: trace `sess.command` bytes end-to-end (russh `exec_request` -> `SSH_DEQUEUE_INFO.command` -> `expand_string` -> env block -> `cmd` expansion). If current code verbatim, bisect vs `v0.28.0-alpha` tag.
