# Part B — Confirmed defects to fix

### D1. `expand_with_lookup` multibyte advance bug (fix)
`crates/sys/oxdock-process/src/lib.rs:109`: `for _ in 0..content.len()` advances a **char** iterator by **byte** count. A placeholder containing any multi-byte char (e.g. `{{ env:héllo }}`) over-advances and swallows characters after `}}`.
**Fix:** advance by `content.chars().count()`.
**Regression tests:** multibyte key expands correctly and trailing text survives; plus parser-edge tests: unclosed `{{`, empty key `{{}}`, whitespace-only key `{{ }}`, stray `}}`, lone `{`, nested-looking text.

### D2. Corrupt/missing tempdir lock ⇒ reclaim (keep behavior, pin with tests)
`crates/sys/oxdock-fs/src/workspace_fs/path.rs:550-554`: `read_lock_pid` returning `None` (missing/empty/garbage/multi-line/non-UTF8 lock) falls through to `remove_dir_all`. This is intended best-effort recovery (marker proves ownership; reclaiming crash-window leaks matters more than the narrow torn-write risk; existing test `cleanup_stale_tempdirs_removes_marked_dirs` path.rs:706 already relies on it).
**Action:** no behavior change. Tests document the semantics explicitly with a comment explaining the trade-off.

### D3. Tempdir creation TOCTOU — marker written before lock (FIX; amends D2 scope)
`GuardedPath::tempdir_with` (path.rs:97-98) calls `write_temp_marker` **before** `write_temp_lock`. During that window a concurrent process running startup cleanup observes marker-present + lock-absent ⇒ `read_lock_pid` → `None` ⇒ reclaim (path.rs:550-554) ⇒ **deletes a live, mid-initialization tempdir**.
**Fix:** invert the sequence — `write_temp_lock(&guard)?` first, then `write_temp_marker(&guard)?`. Cleanup checks marker first (path.rs:544-547), so lock-without-marker is always skipped; the live dir becomes unreachable to cleanup from the moment creation starts.
**Accepted trade-off:** a crash inside the two-write window leaves an unmarked dir that stale-GC never reclaims (vs. today's reclaimable marker-without-lock). Window is ~2 syscalls; a rare empty-dir leak is strictly preferable to deleting an active directory. Document in a comment at the call site.
**Tests pinning the safety envelope (Phase 2):**
- dir with lock file but NO marker → cleanup skips (the invariant the inversion relies on);
- dir with marker but NO lock → cleanup reclaims (D2 semantics unchanged post-fix).

## Conventions every new test must follow

Miri skips only via `#[cfg_attr(miri, ignore = "<reason>")]` (per-test, reason mandatory); `#[cfg(miri)] mod tests` allowed only inside oxdock-fs/process. FS via `GuardedPath`/`PathResolver` only. Env mutation via `TestEnvGuard`/`manifest_env_guard`; `SHELL`/`COMSPEC` under `ENV_LOCK`. Localized `#[allow(clippy::disallowed_*])` only; never `_`-prefixed params. `indoc!` for multiline literals. Platform gates `#[cfg(unix)]`/`#[cfg(windows)]` + `can_create_symlinks` probe. Zero sleeps — determinism via mock plans/hooks everywhere except pre-existing timing tests.

- Dead-PID: rely on reaped-child semantics; assert end-to-end reclamation (not bare liveness probes) → immune to PID reuse.
