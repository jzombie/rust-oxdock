# Plan: GitHub Actions Workflow Commands Integration (#64)

## Context

Issue #64 asks to investigate and document how OxDock scripts can use GitHub Actions workflow commands (log annotations, collapsible groups, job summaries, step outputs) to replace or augment conventional GitHub Actions workflows. The issue is labeled "documentation" and the existing TODO (`TODO-GA-replacement.md`) says: "Start with figuring out how to send status messages."

## Approach: Add `APPEND` command + documentation

OxDock's existing primitives cover most GA patterns:
- `ECHO` → stdout annotations (works everywhere)
- `RUN` → shell commands (cross-platform via `sh -c`/`cmd /C`)
- `WRITE` → file writes (cross-platform, but **overwrites**)

**The gap:** `$GITHUB_OUTPUT`, `$GITHUB_ENV`, and `$GITHUB_STEP_SUMMARY` are **append-only** state files shared across steps. `WRITE` truncates them, destroying previous steps' data. Shell append (`RUN sh -c "echo ... >> ..."`) works but introduces POSIX shell dependency.

**Solution:** Add a native `APPEND` command that uses `std::fs::OpenOptions::new().append(true)` via the `FileSystem` trait — cross-platform, shell-agnostic, sandbox-safe, mock-compatible.

```rust
fn append_file(&self, path: &GuardedPath, contents: &[u8]) -> Result<()>;

// Native implementation (after write_file)
fn append_file(&self, path: &GuardedPath, contents: &[u8]) -> Result<()> {
    if let Some(parent) = path.as_path().parent() {
        fs::create_dir_all(parent)
            .with_context(|| format!("creating dir {}", parent.display()))?;
    }
    let mut file = fs::OpenOptions::new()
        .create(true)
        .append(true)
        .open(path.as_path())
        .with_context(|| format!("opening {} for append", path.display()))?;
    std::io::Write::write_all(&mut file, contents)
        .with_context(|| format!("appending to {}", path.display()))?;
    Ok(())
}

// Miri implementation (after write_file)
fn append_file(&self, path: &GuardedPath, contents: &[u8]) -> Result<()> {
    let rel = normalize_rel(path);
    let binding = self.state_for_guard_rc(path)?;
    binding
        .lock()
        .expect("miri state poisoned")
        .append_file(&rel, contents);
    Ok(())
}
```

### 5. Handler: Implement guarded append

**File: `crates/oxdock-core/src/exec/handlers.rs`**

Add after the `write` handler (~line 521):

```rust
pub(super) fn append<P: ProcessManager>(
    cx: &mut StepCtx<'_, P>,
    idx: usize,
    path: &TemplateString,
    contents: &TemplateString,
) -> Result<()> {
    let ctx = cx.state.command_ctx()?;
    let path_rendered = super::expand_template(path, &ctx);
    let target = cx
        .state
        .fs
        .resolve_write(&cx.state.cwd, &path_rendered)
        .with_context(|| format!("step {}: APPEND {}", idx + 1, path_rendered))?;
    cx.state
        .fs
        .ensure_parent_dir(&target)
        .with_context(|| format!("failed to create parent for {}", target.display()))?;
    let rendered = super::expand_template(contents, &ctx);
    cx.state
        .fs
        .append_file(&target, rendered.as_bytes())
        .with_context(|| format!("failed to append to {}", target.display()))?;
    Ok(())
}
```

**Security:** Path resolved via `cx.state.fs.resolve_write()` (enforces `GuardedPath` sandbox). Write routed through `cx.state.fs.append_file()` (supports mock/memory filesystems in tests).

Appends contents to a file, creating parent directories if needed. Unlike `WRITE` (which

APPEND dist/log.txt "build started"

## GitHub Actions Integration

OxDock scripts can emit GitHub Actions workflow commands using native language primitives.
All examples below are guarded with `[env:GITHUB_ACTIONS]` so they execute on CI runners
but are skipped during local `docs_conformance` tests.

### Log annotations

ECHO writes to stdout, which GitHub Actions intercepts for annotations:

​```oxdock
ECHO "::notice::build started"
ECHO "::warning::something looks off"
ECHO "::error::tests failed"
​```

### Collapsible log groups

​```oxdock
RUN echo "::group::unit tests"
RUN cargo test
RUN echo "::endgroup::"
​```

### Job summary, step outputs, and environment variables

APPEND writes to append-only runner state files without truncating earlier entries:

​```oxdock
[env:GITHUB_ACTIONS] {
  APPEND "{{ env:GITHUB_STEP_SUMMARY }}" "### Build Report\n- Passed: 123\n- Failed: 0\n"
  APPEND "{{ env:GITHUB_OUTPUT }}" "artifact_path=dist/app.tar\n"
  APPEND "{{ env:GITHUB_ENV }}" "NOTEBOOK_MODE=release\n"
}
​```
