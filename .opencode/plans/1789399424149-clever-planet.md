# Plan: Lazily create snapshot tempdir only when needed (issue #131) — rev 7

## Goal
Stop creating the snapshot temp location unconditionally. A `WORKSPACE LOCAL`-only script must not create or leave traces of a snapshot directory. Materialize exactly once, on first actual snapshot need. Defer everywhere: CLI exec paths, `oxdock-build`, `oxdock-macros`, `--shell`/empty-script, logic-test harness.

## Trigger architecture (unchanged principle, new mechanics)
Materialization lives ENTIRELY in the filesystem layer. `oxdock-core` step handlers contain ZERO `ensure()` calls and ZERO trigger lists. Concrete demand is detected structurally at the resolver choke points (`resolve_read` / `resolve_write` / `resolve_workdir`, plus `command_ctx()` resolving its workdir through them). New DSL commands inherit laziness automatically. `ExecState` holds no lazy handle and no gatekeeping logic. This revision fixes rev-6 mechanics per review: NO `&mut` escalation (all resolution stays `&self`), unified single-container ownership in the lazy holder, guarded scratch containment for `CARGO_TARGET_DIR`, and a synchronized cross-clone rebase protocol.

## 1. Lazy holder: single-container unified ownership, flag-gated reads
File: `crates/sys/oxdock-fs/src/workspace_fs/path.rs`; localized allows only.

```rust
pub struct LazyGuardedTempDir {
    // Single initialization container: the GuardedTempDir OWNS its GuardedPath.
    // Pinned heap address via Box; written exactly once. No second slot, no split storage.
    cell: Box<std::sync::OnceLock<GuardedTempDir>>,
    init_lock: std::sync::Mutex<()>, // serializes first-time creation only
    materialized: std::sync::atomic::AtomicBool, // SOLE source of truth for get()
}
impl LazyGuardedTempDir {
    pub fn new() -> anyhow::Result<Self>;
    pub fn is_materialized(&self) -> bool;
    pub fn get(&self) -> Option<&GuardedPath>; // flag-gated, borrow tied to &self via OnceLock
    pub(crate) fn ensure(&self) -> anyhow::Result<&GuardedPath>;
}
// NO take_dir() in any form. NO native path reservation of any kind.
```

- Unified ownership (fixes dual-storage flaw): `GuardedPath` is accessed ONLY as `cell.get().map(|d| d.as_guarded_path())`. The borrow's lifetime is tied to `&self` through `OnceLock::get`, and the path storage is owned by the `GuardedTempDir` inside the same cell — a path reference can never outlive its backing directory guard because both live and die in one container. `Drop` is `GuardedTempDir::drop` itself; no separate cleanup path.
- Native `new()`: stores NOTHING, zero FS I/O, no path strings. Native `ensure()`: takes `init_lock`, rechecks flag, atomically creates via the existing `tempfile::Builder` route (`tempdir_with` internals, lock-before-marker order), `cell.set(tmp)`, `materialized.store(true, Release)`. Concurrent first-touch: losers block on the mutex, then observe the flag and share the winner's directory. Steady-state reads are lock-free (`AtomicBool` + `OnceLock::get`).
- Miri `new()` (`cfg(miri)` ONLY): `TEMP_COUNTER.fetch_add(1)` at the old eager call site (ID order preserved); stores the counter id in a `cfg(miri)` field. Miri `ensure()`: builds the synthetic `GuardedTempDir` (`GuardedTempDir::new(guard(/miri/tempdir-{id}), None, None)`, no host FS), sets cell + flag in the body. Init paths are fully distinct per target.
- Flag discipline: the store executes in `ensure()`'s body on BOTH targets, never solely inside an init closure. `get()` checks `materialized.load(Acquire)` FIRST and returns `None` when false regardless of cell state, so a populated Miri cell still reads unmaterialized until `ensure()`.

## 2. Resolver-integrated laziness with `&self` preserved (interior sync, no escalation)
Files: `workspace_fs/{mod,resolve}.rs`, `oxdock-fs/src/lib.rs` (trait stays `&self`; only ADDITIVE `&mut` switch methods), mock impl.

```rust
pub struct PathResolver {
    root: GuardedPath,               // plain field: virtual anchor (pending) or concrete; root() reads it directly
    current: CurrentRoot,            // Snapshot | Local — mutated ONLY via &mut switch methods
    shared: Arc<SharedSnapshot>,     // cross-clone synchronized state (async-fork coherence)
    build_context: GuardedPath,      // immutable local root
    workspace_root: Option<GuardedPath>,
    backend: Backend,
}
struct SharedSnapshot {
    lazy: LazyGuardedTempDir,                   // ONE physical dir for all clones sharing the Arc
    concrete: OnceLock<GuardedPath>,            // published once at first materialization; read by ALL clones
}
```

- `&self` immutability restored: `resolve_read` / `resolve_write` / `resolve_workdir` keep `&self` signatures UNCHANGED in the trait. Remapping uses only interior synchronization (`OnceLock`, `AtomicBool`, the holder's mutex). Concurrent step execution, async forks, and parallel reads never contend on exclusive borrows; only the single first materialization serializes on `init_lock`. No caller migration, no `&mut` plumbing through `ExecState`/`StepCtx`/`command_ctx()`.
- Choke-point protocol inside each resolve method (all `&self`):
  1. Purely logical check: if `current == Local` (or the request is build-context-rooted, i.e. copy sources), run the pre-existing logic untouched, zero I/O beyond what exists today.
  2. If snapshot-targeted: `let concrete = self.shared.ensure_shared()?` — `ensure_shared()` calls `lazy.ensure()`, then publishes `shared.concrete.get_or_init(|| concrete.clone())` and returns the SHARED reference (not the per-clone field). All joins then use the shared concrete root.
  3. Stale-cwd rebase, centralized here: if the incoming `cwd` is rooted at the per-clone virtual anchor rather than the shared concrete root, strip the anchor prefix to a relative suffix (lexical, in-memory) and re-join onto the shared concrete root before proceeding. No other layer rebases.
- Synchronized rebase (fixes stale-anchor divergence): `root()` is `match (&self.current, self.shared.concrete.get()) { (Local, _) => &self.build_context, (Snapshot, Some(c)) => c, (Snapshot, None) => &self.root /* virtual anchor */ }`. All reads are `&self`-safe field/`OnceLock::get` accesses. When clone A materializes, clone B's next `root()`/resolve call observes the shared concrete root AUTOMATICALLY — no per-clone lazy remap step, no window in which B resolves against a stale anchor for I/O (B's choke point reads `shared.concrete` post-ensure by construction).
- Virtual anchor safety: the anchor is a guard-only lexical base (absolute path value under the system temp dir, constructed with an I/O-free constructor — verify `new_root` performs no stat during implementation, else use the Miri-style struct-literal route). It is NEVER passed to any syscall: every I/O/data path goes through step 2 first when snapshot-targeted; the anchor feeds only lexical joins and the `<snapshot:pending>` display (section 4). Because we never create, open, or follow the anchor path, squatting it gains an attacker nothing — the TOCTOU pattern (reserve-then-`create_dir_all`) does not occur; the only created directory is the atomically-allocated `tempfile` path. Document this invariant at the anchor definition.
- `WORKSPACE` switching: `switch_to_snapshot(&mut self)` (sets `current`, `root :=` fresh virtual anchor, NO I/O) and `switch_to_local(&mut self)` (existing `set_root(build_context)` semantics). `&mut` here is correct and pre-existing in spirit (`set_root` is already `&mut`). `StepCtx.snapshot_root` per-step clones (`steps.rs:217-226`) are DELETED — nothing to capture; the resolver owns the distinction. Add `is_snapshot_pending(&self) -> bool` for display logic.
- Async fork: the fork clone SHARES the same `shared: Arc<SharedSnapshot>` (shallow handle clone) while copying `current`/anchor view. First snapshot-targeted choke point on either side materializes the ONE dir; both sides converge via `shared.concrete` with no pre-spawn `ensure()` anywhere in `oxdock-core`. Non-async `clone_box()` keeps independent-copy semantics.
- Backend audit (verify during implementation): `Backend::new`/cached state must not stat the virtual anchor at construction (`PathResolver::new_lazy` binds the backend against the anchor value). If any backend path stats the root, bind the initial backend against `build_context` (a real dir) and rebind at first `ensure_shared()` publication. `backend.resolve_*(resolved)` already takes concrete paths — expected no-op change.
- Normalization audit (hard requirement): `cwd.join` + containment checks stay lexical/in-memory until post-ensure I/O. Any `canonicalize`/`metadata`/`exists` on the anchor or pre-remap joined path found during implementation moves below step 2. The resolve unit tests run against unmaterialized resolvers with a syscall-recording mock to prove it.

## 3. Process execution unification via `command_ctx()` (`&self`, no scratch creation)
- `command_ctx()` keeps its `&self` signature and resolves its workdir through `resolve_write(cwd, ".")` (lexical self-join; auto-ensures iff snapshot-targeted per section 2). `RUN`/`RUN_EXEC`/async bodies inherit this — no step-level arms, no handler `ensure()` calls (review assertion: `handlers.rs` contains no `ensure` references).
- `CARGO_TARGET_DIR` containment (fixes unbounded-writes flaw WITHOUT reviving per-step creation): the value is a GUARDED absolute path lexically verified to sit inside the designated system-temp hierarchy (guard containment check against the temp root, which exists — no creation), with a high-entropy leaf (`oxdock-cargo-<pid>-<ctr>-<128b-random>`). It is passed as an env string ONLY; our side never calls `ensure()`/`create_dir_all` on it, so non-cargo `RUN echo hi` performs zero FS I/O. Creation, if ever needed, is performed on demand by the child `cargo` invocation itself — standard delegation, and the location is containment-verified rather than an arbitrary relative path. Never derived from `local_root`, never from the snapshot handle.

## 4. Pending display (no fake paths, no local leakage)
- `CWD`-print/inspection renders `is_snapshot_pending()` as the stable sentinel `<snapshot:pending>`; post-materialization it renders the concrete path permanently. Snapshot-context queries never return `local_root` paths and never fabricate native locations.

## As-built notes (implementation complete, all green)

Implemented per rev 7 with these refinements discovered during build:

- **Fail-closed anchor guard**: `check_access` bails (instead of guarding) when
  the candidate is anchor-rooted while pending, since `guard_path` would
  otherwise CREATE the anchor. All `&self.root` field uses in `access.rs`,
  `io.rs`, and `git/mod.rs` route through `effective_root()`.
- **`is_snapshot_pending` keys off concrete publication**, not the lazy flag,
  so eager constructors (which pre-publish) never read pending.
- **Two choke riders**: bare `LS` and `GLOB` resolve `cwd`/`"."` through
  `resolve_read` first (they need a concrete root, not just a resolved child).
- **Shared error composer**: `compose_error_with_snapshot` is used by both
  eager and lazy runners so chains render identically; `enrich_lazy_error` is
  public for the test harness (fixes `copy_broken_symlink` error-text parity).
- **`CARGO_TARGET_DIR` scratch uses monotonic `Instant` + counter** (no
  wall-clock, no pid) after Miri isolation rejected `SystemTime::now()`.
- **Harness**: `set_build_context` added (safe: native backend stateless,
  Miri backend role-keyed); snapshot setup / snapshot-build-context cases
  pre-materialize explicitly; post-run snapshot re-read for verification.
- **`ExecutionResult.snapshot: Arc<LazyGuardedTempDir>`** with
  `has_snapshot()` / `snapshot_path()`; `oxdock-build`/`oxdock-macros` emit an
  empty output dir via `clear_materialize_dir` (new, shared) when pending.
