# Architecture Plan: Static Enum Dispatch via Macro (v8)

## Problem

Command metadata is scattered across four disconnected sources. Adding or modifying a command requires touching 6 files. The test harness spawns ~50 separate `cargo run` processes per test run, making the feedback loop painfully slow. The goal is **compile-time extensibility** + **in-process execution**.

---

## Critical Flaws Addressed

| # | Flaw | Fix |
|---|------|-----|
| 1 | Circular crate dependency (`execute` in parser trait) | `CommandSpec` has no `execute` — parsing/metadata/lowering only |
| 2 | `CommandSpec::lower` lacks flags | `lower(flags, args)` — unified signature |
| 3 | `macro_rules!` can't iterate const slices | `build.rs` writes `#[test]` fns directly |
| 4 | `WithIoBlock` missing from dispatch | Explicit match arm |
| 5 | `resolve_arg_pure` ignores absent args | `resolve_opt_arg_pure` accepts `Option<&Arg>` |
| 6 | `dyn` dispatch overhead | Static enum dispatch — zero heap, zero vtable |

---

## Architecture Overview

```
oxdock-parser                              oxdock-core
┌──────────────────────────┐               ┌──────────────────────────┐
│ CommandSpec trait         │               │ define_pipeline! {       │
│   const NAME             │               │   Write(WriteCmd),       │
│   fn metadata()          │               │   Read(ReadCmd),         │
│   fn lower(flags, args)  │               │   ...                    │
│   (NO execute)           │               │ }                        │
│                          │               │                          │
│ StepKind enum (here!)    │               │ Generates:               │
│   Write(path, contents)  │◄──────────────│   - lower_command()      │
│   AssertFile(hash, ...)  │               │   - execute_command()    │
│   For { .. }             │               │   - all_metadata()       │
│   WithIoBlock { .. }     │               │                          │
│                          │               │ handlers::write(), etc.  │
│ parse_script(lower)      │               │ (called by generated     │
└──────────────────────────┘               │  execute_command match)  │
                                           └──────────────────────────┘
```

**Key insight:** `CommandSpec` in `oxdock-parser` owns **no execution types**. `StepCtx`, `ProcessManager`, and handler functions live exclusively in `oxdock-core`. The `define_pipeline!` macro generates `execute_command` by matching `StepKind` variants and calling handler functions directly — no trait dispatch needed.

---

## Solution: 7 Components

### 1. `CommandSpec` Trait (`oxdock-parser/src/command.rs`)

**No `execute` method.** Pure parsing + metadata + lowering:

```rust
use crate::ast::{Arg, IoBinding};
use anyhow::Result;

pub struct ArgSpec {
    pub name: &'static str,
    pub arg_type: &'static str,
    pub io: IoDirection,
    pub index: usize,
    pub required: bool,
    pub fallback_stream: Option<Stream>,
}

pub struct FlagSpec {
    pub name: &'static str,
    pub long: &'static str,
    pub value_type: FlagValueType,
    pub required: bool,
    pub description: &'static str,
}

pub struct CommandMeta {
    pub name: &'static str,
    pub syntax: &'static str,
    pub summary: &'static str,
    pub description: &'static str,
    pub args: &'static [ArgSpec],
    pub flags: &'static [FlagSpec],
    pub default_output: Option<Stream>,
    pub examples: &'static [Example],
}

pub struct Example {
    pub name: &'static str,
    pub code: &'static str,
}

/// Parsing + metadata + lowering trait. No execution types.

    const NAME: &'static str;

    fn metadata() -> CommandMeta;
```

### 3. `define_pipeline!` Macro (`oxdock-core/src/pipeline.rs`)

Generates lowering dispatch (calls `CommandSpec::lower`) + execution dispatch (calls handlers directly):

```rust
#[macro_export]
macro_rules! define_pipeline {
    (
        $( $pat:pat => ($cmd_type:ty, $handler:path) ),* $(,)?
    ) => {
        // ── Generated lowering dispatch (includes flag stripping) ──
        pub fn lower_command(
            name: &str,
            raw_args: Vec<$crate::Arg>,
        ) -> Result<$crate::StepKind> {
            match name {
                // Guard avoids qualified path E0533 — string comparison works
                $( s if s == <$cmd_type as $crate::CommandSpec>::NAME => {
                    let meta = <$cmd_type as $crate::CommandSpec>::metadata();
                    let (flags, positional) = $crate::strip_flags(raw_args, &meta)?;
                    <$cmd_type as $crate::CommandSpec>::lower(flags, positional)
                } )*
                _ => anyhow::bail!("unknown command: {name}"),
            }
        }

        // ── Generated execution dispatch (calls handlers directly) ──
        pub fn execute_command<P: ProcessManager>(
            step: &$crate::StepKind,
            cx: &mut $crate::StepCtx<'_, P>,
        ) -> Result<()> {
            match step {
                $( $crate::StepKind::$pat => $handler(cx, step), )*
                // ALL structural variants handled explicitly
                $crate::StepKind::WithIo { bindings, cmd } => $crate::handlers::with_io(cx, bindings, cmd),
                $crate::StepKind::WithIoBlock { bindings } => $crate::handlers::with_io_block(cx, bindings),
                $crate::StepKind::For { .. } => $crate::handlers::for_loop(cx, step),
                $crate::StepKind::If { .. } => $crate::handlers::if_then(cx, step),
                $crate::StepKind::Assign { .. } => $crate::handlers::assign(cx, step),
            }
        }

        // ── Generated metadata registry ──
        pub fn all_metadata() -> Vec<$crate::CommandMeta> {
            vec![
                $( <$cmd_type as $crate::CommandSpec>::metadata(), )*
            ]
        }
    };
}
```

### 5. Flag Handling — No Expression Destruction, No Allocations

```rust
pub fn strip_flags(
    args: Vec<Arg>,
    meta: &CommandMeta,
) -> Result<(Vec<(String, Arg)>, Vec<Arg>)> {
    if meta.flags.is_empty() {
        return Ok((Vec::new(), args));
    }

    let mut flags = Vec::new();
    let mut positional = Vec::new();
    let mut iter = args.into_iter();
    while let Some(arg) = iter.next() {
        match &arg {
            Arg::String(s) if s == "--" => {
                positional.extend(iter);
                break;
            }
            Arg::String(s) if s.starts_with("--") => {
                let matched = meta.flags.iter().find(|f| {
                    s == f.long || s.starts_with(f.long) && s.as_bytes().get(f.long.len()) == Some(&b'=')
                });
                match matched {
                    Some(flag_meta) => {
                        let value = if let Some(eq_pos) = s.find('=') {
                            Arg::String(s[eq_pos + 1..].to_string())
                        } else if matches!(flag_meta.value_type, FlagValueType::Flag) {
                            Arg::String("true".into())
                        } else {
                            iter.next()
                                .ok_or_else(|| anyhow!("{} requires a value", flag_meta.long))?
                        };
                        flags.push((flag_meta.name.to_string(), value));
                    }
                    None => {
                        // Unknown flag on a command that has flags — reject
                        return Err(anyhow!("unknown flag {} for command {}", s, meta.name));
                    }
                }
            }
            _ => positional.push(arg),
        }
    }
    Ok((flags, positional))
}
```

**Expression handling:** The PEG parser produces `Arg::String("--hash={{ $digest }}")` for all flag tokens (atomic rule returns flat string). `strip_flags` extracts `Arg::String("{{ $digest }}")`. At runtime, `expand_string` processes the template. No AST node is destroyed — templates in `Arg::String` are always resolved at runtime.

## Implementation Phases

### Phase 1: Trait + StepKind + Macro Foundation
- Define `CommandSpec` trait (metadata + lowering only, no execute) in `command.rs`
- Keep `StepKind` in `ast.rs` (Arg-based variants)
- Implement `define_pipeline!` macro (generates `lower_command` + `execute_command`)
- Add `strip_flags` (no allocations, preserves Arg AST)
- **Re-export parser types from `oxdock-core`** — add `pub use oxdock_parser::{CommandSpec, CommandMeta, Arg, StepKind, strip_flags};` to `oxdock-core/src/lib.rs` so `$crate::` paths in `define_pipeline!` resolve correctly
- Verify: `cargo build -p oxdock-parser -p oxdock-core`

### Phase 2: Generic PEG + Lowering Integration
- Remove command-specific PEG rules from `dsl.pest`
- `parse_script()` accepts `lower(name, flags, args)` fn parameter
- Generic `instruction` rule extracts command name + raw args
- Wire `lower_command` from `define_pipeline!` into parser
- Verify: `cargo test -p oxdock-parser`

### Phase 3: Migrate Built-In Commands
- Implement `CommandSpec` for all 24 built-in commands
- Add `*_dispatch` handler functions in `handlers.rs`
- `define_pipeline!` invocation lists all commands + handlers
- Wire `execute_command` into `steps.rs` dispatch
- **Standardize handler parameter ordering** — all execution handlers (both command dispatch and structural) must accept `(cx, step)` uniformly; `define_pipeline!` must pass args in the same order for every match arm
- Verify: `cargo test --workspace --tests`

### Phase 4: Pure Arg Resolution
- Add `ArgValue` + `resolve_opt_arg_pure`
- Update handler signatures
- Verify: `cargo test -p oxdock-core`

### Phase 5: Docs
- Generate `07-command-body.md` from `all_metadata()`
- Verify: `cargo run -p docs-gen`

#### 6a. `build.rs` — Test Generation

Scans `fixtures/commands/ast_commands/cases/` and emits one `#[test]` fn per case directory.

**Critical decisions (code review fixes):**

- **Use `dir_name` for Rust identifiers** — directory names are all snake_case, guaranteeing valid Rust syntax. No TOML scraping needed.
- **Recursive `rerun-if-changed`** — walk the entire `fixtures/commands/` tree and emit `cargo:rerun-if-changed` for every file (including `script.oxdock`, `coverage.toml`), plus `crates/oxdock-parser/src/ast.rs` (StepKind changes trigger rebuild).
- **Pass `Result` to verification** — no `.expect()` on parse results. Generated body chains `parse_script → run_ast_case → verify_ast_result`, allowing negative test cases to work.

```rust
// crates/oxdock-logic-tests/build.rs
use std::fs;
use std::io::Write;
use std::path::Path;
use indoc::indoc;

fn main() {
    let cases_dir = Path::new("fixtures/commands/ast_commands/cases");
    println!("cargo:rerun-if-changed=fixtures/commands/ast_commands/coverage.toml");
    println!("cargo:rerun-if-changed=../oxdock-parser/src/ast.rs");

    // Recursively register all fixture files
    fn walk_dir(dir: &Path) {
        if let Ok(entries) = fs::read_dir(dir) {
            for entry in entries.flatten() {
                let path = entry.path();
                if path.is_dir() { walk_dir(&path); }
                else { println!("cargo:rerun-if-changed={}", path.display()); }
            }
        }
    }
    walk_dir(cases_dir);

    // Discover case directories
    let mut cases: Vec<String> = Vec::new();
    for entry in fs::read_dir(cases_dir).unwrap().flatten() {
        if entry.path().is_dir() && entry.path().join("case.toml").exists() {
            let name = entry.file_name().to_string_lossy().into_owned();
            cases.push(name);
        }
    }
    cases.sort();

    let out_dir = std::env::var("OUT_DIR").unwrap();
    let out_path = format!("{out_dir}/command_cases.rs");
    let mut out = fs::File::create(&out_path).unwrap();

    for dir_name in &cases {
        let fn_name = dir_name.replace('-', "_");
        writeln!(
            out,
            indoc! {r#"
                #[test]
                fn case_{fn_name}() {{
                    let case = oxdock_logic_tests::ast_case::load_ast_case("{dir_name}");
                    let root = oxdock_logic_tests::ast_case::AstCaseRoot::new(&case);
                    let parse_res = oxdock_core::parse_script(&case.script, oxdock_core::lower_command);
                    let exec_res = parse_res.and_then(|steps| {{
                        oxdock_logic_tests::ast_case::run_ast_case(&case, &steps, &root)
                    }});
                    oxdock_logic_tests::ast_case::verify_ast_result(&exec_res, &case, &root);
                }}
            "#},
        )
        .unwrap();
    }
}
```

#### 6b. `lib.rs` — `ast_case` Module

Extract core logic from `ast_commands/src/main.rs` into a public `ast_case` module. Provides:

- **`AstCaseSpec`** — case metadata (name, script, build_context, setup, stdin, env, expect_error, expectations, pipes)
- **`AstCaseRoot`** — RAII wrapper for snapshot + local tempdirs

- **`run_ast_case(case, steps, root) -> Result<()>`** — executes steps in-process with IO config
- **`verify_ast_result(result, case, root)`** — matches `Result` against `case.expect_error`; asserts file/dir/hash/ls/cwd/pipe expectations
- **`assert_coverage()`** — reads `coverage.toml`, extracts `StepKind` variants from `ast.rs`, validates coverage
