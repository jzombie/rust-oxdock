# oxdock-markdown-plugin

Markdown rendering for OxDock scripts through the Engine facade: MAP to table conversion callable as a DSL statement or inside placeholders.

> Part of the [OxDock](https://github.com/jzombie/rust-oxdock) workspace.

## Overview

The MARKDOWN module renders record data as Markdown tables for
reports and digests: `MAP_TO_MD_TABLE` takes one MAP (or a LIST of
MAPs sharing keys) and returns aligned pipe-table text with union
columns, padded cells, and strict errors on shapes with no table in
them. Import it with `IMPORT [STD, MARKDOWN]` in a runner that
registers the host module on the [Engine facade](https://github.com/jzombie/rust-oxdock/blob/main/crates/oxdock-core/src/exec/engine.rs).
It works both as a DSL statement and inside placeholders as
`{{ MARKDOWN::MAP_TO_MD_TABLE($var) }}`. Table rendering and cell
escaping live in the pure `markdown` module, the single source the
host wrapper calls into.

```oxdock
IMPORT [STD, MARKDOWN]

# One MAP renders one body row under the key header.
LET $row: MAP<name: STRING, stars: INT> = {name: "demo", stars: 3}
LET $table: STRING = MAP_TO_MD_TABLE($row)

# The header names the keys, the row carries the values.
ASSERT_CONTAINS $table "| name | stars |"
ASSERT_CONTAINS $table "| demo | 3     |"
```

## Functions

Callable as `MODULE::NAME(...)` in expressions (or bare `NAME(...)` with the module imported via `IMPORT`). Introspectable from scripts with `FUNCTIONS()` and `DESCRIBE(name)`.

### MAP_TO_MD_TABLE

**Signature:** `MAP_TO_MD_TABLE($map: ANY) -> STRING`

**Contexts:** AST, RPN

**Parameters:**
- `$map` (ANY): Record data: a MAP renders one row, a LIST of MAPs renders one row per entry with union columns.

**Returns:** `STRING`

Render record data as an aligned Markdown table: one row per MAP,
one column per key. Fails strict on shapes with no table in them.
